PostgreSQL

Sistema gestor de base de datos SQL

none

(1) Instalación en el servidor

1. Hay que instalar el servicio de PostgreSQL y otras dependencias en el servidor:

apt-get update
apt-get install -y postgresql postgresql-contrib sudo

2. Para verificar que se ha instalado correctamente se debe poder ejecutar el siguiente comando y también ver el estado del servicio de PostgreSQL:

psql --version
systemctl status postgresql

En caso de que el servicio de un fallo al iniciar se debe realizar la siguiente comprobación:

1. Ver los detalles exactos del fallo:

journalctl -u postgresql -n 50 --no-pager

2. Consultar los logs de PostgreSQL:

tail -f /var/log/postgresql/postgresql-*.log

3. Verificar que el puerto 5432 no esté en uso por otro programa:

ss -tulpn | grep 5432

4. Verificar que el disco tiene espacio suficiente:

df -h

3. Para que el servicio de PostgreSQL se inicie automáticamente al iniciar el equipo:

systemctl enable --now postgresql

4. Hay que reiniciar el servicio:

systemctl restart postgresql

5. Por último hay que verificar si el servidor está preparado para aceptar conexiones:

pg_isready -h [IP_servidor] -p [Puerto_servidor]

(2) Asignar una IP estática en el servidor

En el servidor se puede asignar una IP estática desde la interfaz gráfica o, si es un sistema Ubuntu Server, modificando el fichero de configuración de Netplan.

1. Antes de editar el fichero se debe realizar una copia de seguridad:

cp /etc/netplan/50-cloud-init.yaml /etc/netplan/50-cloud-init.yaml.backup

2. Tras la copia de seguridad hay que editar el fichero y asignar la siguiente configuración, modificando los valores con una configuración de red válida:

nano /etc/netplan/50-cloud-init.yaml
network:
    version: 2
    ethernets:
        [Interfaz_de_red]
            dhcp4: false
            addresses:
              - [IP_estática/Máscara_CIDR]
            routes:
              - to: default
                via: [IP_default_gateway]
            nameservers:
              addresses:
                - 1.1.1.1
                - 1.0.0.1

3. Al guardar el fichero hay que probar que la configuración sea válida:

netplan try

4. Si el comando anterior no dió ningún error, se puede aplicar la nueva configuración:

netplan apply

5. Para comprobar que la IP estática se configuró correctamente hay que ver la IP actual del equipo:

hostname -I

(3) Instalación en el cliente

1. Hay que instalar el servicio de PostgreSQL para clientes:

apt-get update
apt-get install -y postgresql-client

2. Una vez instalado se puede ejecutar el siguiente comando para crear una conexión a una base de datos del servidor:

psql -h [IP_servidor] -p [Puerto_servidor/:5432] -U [Nombre_usuario] -d [Nombre_base_de_datos]

(4) Gestionar los clústers

Para ver según el sistema la versión, nombre puerto, estado, propietario, ruta de datos y registros de cada clúster:

pg_lsclusters

En sistemas Debian y Ubuntu se permite gestionar varias versiones y clústers.
El clúster por defecto se llama main.

Para detener un cluster primero se debe saber que nombre tiene con el comando anterior:

pg_ctlcluster [Versión_PostgreSQL] [Nombre_clúster] stop

Para iniciar un clúster que se encuentra detenido:

pg_ctlcluster [Versión_PostgreSQL] [Nombre_clúster] start

(5) Permitir conexiones remotas

1. Primero debes copiar la ruta local que indique el comando SHOW hba_file;:

sudo -u postgres psql
SHOW hba_file;
\q

2. Debes editar el fichero que se encuentra en la ruta del paso 1 con nano.

3. Dentro del fichero del paso 2 hay que añadir una nueva línea indicando la dirección de red cuyos equipos tendrán permisos de hacer conexiones remotas:

host all all [Dirección_red/Máscara] scram-sha-256

4. Se debe reiniciar el servicio de PostgreSQL para aplicar los cambios:

systemctl restart postgresql

5. Si el firewall está activado, se debe crear una regla para permitir las conexiones de IPs que estén en el rango de la dirección de red hacia el puerto de PostgreSQL:

ufw allow from [Dirección_red/Máscara] to any port [puerto_postgresql] proto tcp
ufw reload

Gestionar la base de datos

Para entrar a la base de datos hay que ejecutar el comando psql con el usuario administrador postgres:

sudo -u postgres psql

Otra manera de ejecutar comandos SQL directamente es:

sudo -u postgres psql -c '[Comando_SQL];'

Comandos básicos de SQL:

Con \? se muestra una ayuda de los comandos. Con \h se muestra una ayuda de la sintaxis de SQL. 
\l
 Lista todas las bases de datos existentes en el clúster. 
\c [Nombre_base_datos]
 Se conecta a la base de datos indicada mediante su nombre. 
\du
 Lista los roles y usuarios, junto con sus atributos y permisos globales. 
\dt
 Lista las tablas visibles en una base de datos. 
\d [Nombre_tabla]
 Muestra la estructura de la tabla con sus valores por defecto. 
\conninfo
 Muestra la información de la conexión actual con la base de datos. 
SELECT current_database(), current_user;
 Muestra a que base de datos se está conectado y con que usuario. 
SELECT current_timestamp;
 Muestra la fecha y hora en la que se ejeucta esa consulta. 
\q
 Cierra la sesión y finaliza el comando psql.

Configuraciones del sistema:

SELECT version();
 Indica la versión del servicio de PostgreSQL en formato largo. 
SHOW server_version;
 Indica la versión del servicio de PostgreSQL en formato numérico. 
SHOW data_directory;
 Muestra la ruta del directorio de datos del clúster. 
SHOW config_file;
 Devuelve la ruta absoluta del fichero principal de configuración. 
SHOW hba_file;
 Devuelve la ruta absoluta del fichero de autenticación de clientes. 
SHOW ident_file;
 Devuelve la ruta absoluta del fichero donde se mapean los usuarios del S.O. a roles internos de la base de datos. 
SHOW port;
 Muestra el puerto TCP/IP en el que el servidor está escuchando conexiones entrantes (por defecto suele ser 5432).

Registros del sistema:

SHOW log_destination;
 Muestra la ruta del directorio donde se guardan los registros. 
SHOW logging_collector;
 Indica si PostgreSQL está recopilando los mensajes de stderr y escribiéndolos en ficheros (on/off). 
SHOW log_directory;
 Muestra la ruta del directorio donde se guardan los ficheros de log. 
SHOW log_filename;
 Muestra el patrón utilizado para nombrar los ficheros de log. 
pg_current_logfile
 Comando de Linux. Muestra la ruta del fichero de log que está utilizando actualmente logging_collector. Si no devuelve nada entonces logging_collector está desactivado. 
sudo grep -i 'error\|fatal\|panic' [Ruta_fichero_log]
 Comando de Linux. Del fichero log filtra solo se muestran los errores.

Para verificar por cual puerto está escuchando el servicio de PostgreSQL (es lo mismo que la consulta SQL SHOW port;):

ss -ltnp | grep postgres

Creación de usuarios

Para crear un nuevo usuario en la base de datos:

CREATE USER [Nombre_usuario] WITH PASSWORD '[Contraseña_usuario]';

Una vez se haya creado el usuario, se puede comprobar que aparece en el siguiente listado:

\du

Creación de bases de datos

Para crear una nueva base de datos se debe de especificar un usuario propietario:

CREATE DATABASE [Nombre_base_datos] OWNER [Nombre_usuario_propietario];

Una vez se haya creado la base de datos, se puede comprobar que aparece en el siguiente listado:

\l

Creación de una tabla

Para crear una nueva tabla primero se debe especificar en que base de datos se creará:

\c [Nombre_base_datos]
CREATE TABLE [Nombre_tabla] (
    [Nombre_columna] [Tipo_Valor] [Otras_opciones],
    (...)
 );

Una vez se haya creado la tabla, se puede comprobar que aparece en el siguiente listado:

\dt

Insertar valores en una columna de una tabla

Para insertar datos en una tabla existente se debe usar los siguientes comandos:

\c [Nombre_base_datos]
INSERT INTO [Nombre_tabla] ([Nombre_columna])
VALUES ('Valor_a_insertar');

Una vez se haya insertado la columna, se puede comprobar una consulta SQL:

SELECT * FROM [Nombre_tabla];
