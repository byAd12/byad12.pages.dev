LDAP - Servidor

Lightweight Directory Access Protocol

none

Importante

Un dominio se divide en 2 partes: el nombre de dominio (antes del punto) y el TLD (después del punto):

[NOMBRE_DOMINIO].[TLD_DOMINIO]

(1) Instalación

Primero hay que instalar el servidor LDAP - slapd junto a las utilidades necesarias - ldap-utils:

apt-get update
apt-get install -y slapd ldap-utils

Al ejecutar el comando de instalación, el sistema pedirá una contraseña para la gestión del servicio del servidor LDAP.

(2) Comprobación

El servicio debe estar en modo active:

systemctl status slapd

El servicio slapd debe tener un puerto en modo LISTEN:

ss -pltu | grep slapd

Al no haber configurado nada, deberá devolver NODOMAIN:

slapcat

Se debe poder ejecutar el siguiente comando para ver con que usuario estamos autentificados:

ldapwhoami -x

La conexión al servicio se realiza con el usuario anonymous si no definimos nada.

(3) Configuración

Una vez se hayan instalado los paquetes con APT hay que configurar mediante el servicio LDAP:

dpkg-reconfigure slapd

Respuestas que va a solicitar el asistente en orden:

  1. Omit OpenLDAP server configuration? -> no.
  2. DNS domain name -> (el nombre de dominio + TLD que se utilizará para crear objetos en el servicio LDAP).
  3. Organization name -> (el nombre de la organización).
  4. Administrator password -> (definir una contraseña para el administrador del servicio LDAP).
  5. Confirm password -> (repetir la contraseña del administrador del servicio LDAP).
  6. Do you want the database to be removed when slapd is purged? -> no.
  7. Move old database? -> yes.

Tras realizar el comando anterior hay que comprobar que el siguiente comando devuelve un objeto con toda la configuración del dominio LDAP:

slapcat

Ahora hay que comprobar que se puede entrar al servicio con el usuario admin:

ldapwhoami -x -D "cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]" -W

Solicitará la contraseña que se configuró en el asistente. Si devuelve el contenido entre comillas, entonces el servicio está bien configurado.

Formato de fichero de configuración

Los ficheros con extensión .ldif se utilizan para definir varios objetos a la vez para luego añadirlos a la BD con el comando ldapadd:

# Objeto 1
dn: [URI]
    [Atributo]: [Valor_atributo]
    ...

# [Se debe poner obligatoriamente una línea vacía antes de añadir otro objeto]
# Objeto 2
dn: [URI]
    [Atributo]: [Valor_atributo]
    ...
dn: [URI]
 "dn" significa "Distingushed Name".
Es una URI que diferencia individualmente a todos los objetos de la BD.

Crear una unidad organizativa

1. Dentro de un fichero con formato .ldif hay que definir el siguiente objeto:

dn: ou=[UO],dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]
objectClass: top
objectClass: organizationalUnit
ou: [UO]

UO: Nombre personalizado que tendrá la unidad organizativa.
NOMBRE_DOMINIO: Nombre del dominio sin el TLD (.es, .com. .net, ...).
TLD_DOMINIO: TLD del dominio (.es, .com. .net, ...) sin el punto.

2. Una vez se haya definido el objeto se debe añadir a la base de datos:

ldapadd -x -D cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO] -W -f [RUTA_FICHERO].ldif

3. Hay que comprobar si en la base de datos está la nueva unidad organizativa:

slapcat

Crear un grupo

1. Dentro de un fichero con formato .ldif hay que definir el siguiente objeto:

dn: cn=[NOMBRE_GRUPO],ou=[UO],dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]
objectClass: top
objectClass: posixGroup
gidNumber: [N_GID]
cn: [NOMBRE_GRUPO]

NOMBRE_GRUPO: Nombre personalizado que tendrá el grupo.
UO: Unidad organizativa a la que pertenecerá.
NOMBRE_DOMINIO: Nombre del dominio sin el TLD (.es, .com. .net, ...).
TLD_DOMINIO: TLD del dominio (.es, .com. .net, ...) sin el punto.
N_GID: Número identificador entero y único del grupo.

2. Una vez se haya definido el objeto se debe añadir a la base de datos:

ldapadd -x -D cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO] -W -f [RUTA_FICHERO].ldif

3. Hay que comprobar si en la base de datos está el nuevo grupo:

slapcat

Crear un usuario

1. Hay que calcular el hash de la contraseña con el siguiente comando:

slappasswd

Pedirá que se ingrese una contraseña para poder devolver su hash, como por ejemplo:

{SSHA}jJ/Sl2m---5HeZJP

2. Dentro de un fichero con formato .ldif hay que definir el siguiente objeto:

dn: uid=[NOMBRE_USUARIO],ou=[UO],dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]
objectClass: top
objectClass: account
objectClass: posixAccount
uid: [NOMBRE_USUARIO]
cn: [NOMBRE_COMÚN]
userPassword: [CONTRASEÑA]
gecos: [NOMBRE_COMPLETO]
uidNumber: [N_UID]
gidNumber: [N_GID]
homeDirectory: /home/[NOMBRE_USUARIO]
loginShell: [SHELL]

UO: Unidad organizativa a la que pertenecerá.
NOMBRE_DOMINIO: Nombre del dominio sin el TLD (.es, .com. .net, ...).
TLD_DOMINIO: TLD del dominio (.es, .com. .net, ...) sin el punto.
NOMBRE_USUARIO: Nombre personalizado que tendrá el usuario.
NOMBRE_COMÚN: Nombre común personalizado que tendrá el usuario.
NOMBRE_COMPLETO: Nombre completo personalizado que tendrá el usuario.
CONTRASEÑA: El hash de la contraseña (calculado en el paso 1).
N_UID: Número identificador entero y único del usuario.
N_GID: Número identificador entero del grupo. 0 = Ninguno.
SHELL: /bin/bash, /bin/sh.

3. Una vez se haya definido el objeto se debe añadir a la base de datos:

ldapadd -x -D cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO] -W -f [RUTA_FICHERO].ldif

4. Hay que comprobar si en la base de datos está el nuevo usuario:

slapcat

Crear un usuario con un perfil móvil

Hay que hacer lo mismo que en el apartado "Crear un usuario" pero cambiando la ruta de homeDirectory a la carpeta donde se almacenarán estos perfiles:

homeDirectory: /[CARPETA_MÓVIL]/[NOMBRE_USUARIO]

Modificar un objeto

1. Dentro de un fichero con formato .ldif hay que definir el siguiente objeto:

dn: [DN_COMPLETO]
changetype: modify
replace: [PROPIEDAD_CAMBIAR]
[PROPIEDAD_CAMBIAR]: [VALOR_CAMBIAR]

DN_COMPLETO: URI que identifique al objeto dentro de la base de datos.
PROPIEDAD_CAMBIAR: Nombre de la propiedad a modificar.
VALOR_CAMBIAR: El nuevo valor que se le va a asignar a esa propiedad.

Recuerda: Para hacer 2 cambios a la vez se pone ambos objetos separados por una línea en blanco.

2. Una vez se haya definido el objeto se debe aplicar en la base de datos:

ldapmodify -x -D "cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]" -W -f [RUTA_FICHERO].ldif

3. Hay que comprobar si se hizo el cambio en la base de datos:

slapcat

Eliminar un objeto

Primera forma - con el comando ldapdelete:

ldapdelete -x -D "cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]" -W "[DN_COMPLETO]"

DN_COMPLETO: URI que identifique al objeto dentro de la base de datos.

Segunda forma - crear un fichero .ldif con el siguiente contenido:

dn: [DN_COMPLETO]
changetype: delete

Y luego aplicar ese objeto en la base de datos:

ldapmodify -x -D "cn=admin,dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]" -W -f [RUTA_FICHERO].ldif

Buscar un objeto

Con el comando ldapsearch se puede buscar objetos identificados por su URI:

ldapsearch -xLLL -b "dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]" [BÚSQUEDA] (ENSEÑAR)

BÚSQUEDA: El objeto que vamos a buscar según un valor. Por ejemplo: "uid=xx", "gid=xx".
ENSEÑAR: Es opcional. Son los valores del objeto a buscar que se quieren enseñar. Por ejemplo: "cn", "uid", "gid".

LDAP - Cliente

Conexión de un cliente al servicio LDAP de un servidor

1. Primero hay que añadir un registro DNS interno que apunte al dominio LDAP mediante el siguiente fichero:

nano /etc/hosts

Hay que añadir una línea en el fichero con el siguiente formato:

[IP_SERVIDOR]    [NOMBRE_DOMINIO].[TLD_DOMINIO]

2. Primero hay que instalar los servicios necesarios:

apt-get update
apt-get install -y libnss-ldapd libpam-ldapd nslcd

Va a pedir una serie de preguntas, a las cuales hay que responder de la siguiente manera:

  1. LDAP server URI -> ldap://[IP_SERVIDOR]
  2. LDAP server search base -> dc=[NOMBRE_DOMINIO],dc=[TLD_DOMINIO_SIN_PUNTO]
  3. Name services to configure -> seleccionar: passwd, group, shadow

Si el proceso de instalación falla o no realiza las preguntas anteriores, hay que reconfigurar el servicio con:

dpkg-reconfigure ldap-auth-config

3. Hay que verificar que en el siguiente fichero se haya añadido la palabra ldap al final de las líneas passwd, group y shadow:

cat /etc/nsswitch.conf

4. Para que el usuario pueda crear su carpeta personal al iniciar sesión hay que ejecutar el siguiente comando y habilitar la opción Create home directory on login:

pam-auth-update

Tras ejecutar el comando anterior, hay que verificar que en el fichero /etc/pam.d/common-session exisa la siguiente línea, que indica que se debe crear la carpeta personal del usuario:

session optional                        pam_mkhomedir.so

5. Si el servidor LDAP tiene algún usuario creado, se debe verificar que el cliente pueda ver sus nombres con el siguiente comando:

getent passwd

En caso de que no aparezca ningún usuario, hay que reiniciar el servicio LDAP:

systemctl restart nslcd

6. Por último se puede iniciar sesión con un usuario del servidor en el equipo cliente para comprobar que funcione correctamente:

login [USUARIO_LDAP]

Si se habilitó la opción para crear las carpetas personales, al iniciar sesión debe aparecer una línea que ponga "Creating directory [...]".
