SAMBA

Compartir carpetas entre Linux y Windows

none

Alojar una carpeta en un servidor Linux

1. Creación de carpeta, permisos y usuarios:

mkdir /[Carpeta_a_compartir]
groupadd [Nombre_grupo]
useradd -g [Nombre_grupo] [Nombre_usuario]
passwd [Nombre_usuario]
chown [Nombre_usuario]:[Nombre_grupo] /[Carpeta_a_compartir]
chmod permisos /[Carpeta_a_compartir]

El usuario debe tener un nombre igual que en la máquina Windows en la que se vaya a iniciar sesión.

Importante: Los usuarios no pueden listar el contenido de la carpeta sin el permiso x (eXecute).

Riesgo de seguridad: Deben configurarse los permisos locales antes de compartir la carpeta ya que, durante el tiempo que se comparte sin los permisos adecuados, se estará permitiendo accesos no deseados al recurso que se esté compartiendo.

Nota de seguridad: Si se usa este usuario solo para que pueda acceder de forma remota, se puede limitar su acceso a solo remoto y evitar que pueda iniciar sesión en nuestro sistema local mediante el parámetro -s /usr/sbin/nologin en el comando useradd.


2. Reconocer al usuario:

Hay que meter al usuario en una base de datos independiente a /etc/shadow para que este usuario sea roconocido en sistemas Windows.

Antes de nada hay que crear el usuario en el sistema local:

useradd (Opciones) [Nombre_usuario]
passwd [Nombre_usuario]

Hay que configurar ese usuario para que sea reconocible como un usuario para Windows:

smbpasswd -a [Nombre_usuario]

La contraseña que se asigna con smbpasswd debe coincidir con la que se usará para iniciar sesión desde Windows, pero no tiene que coincidir con la contraseña del usuario Linux.

Una vez se reconozca al usuario se puede confirmar con el siguiente comando que enseña el UID, GID y nombre de los usuarios compatibles con Windows:

pdbedit -L

3. Instalar paquetes:

apt-get install -y samba

Una vez instalado se crean 3 servicios para gestionar la transferencia de datos, permisos y visibilidad del servidor: samba-ad-dc, nmbd y smbd.

Además se crea una carpeta esencial que contiene los ficheros de configuración: /etc/samba.


4. Editar la configuración:

nano /etc/samba/smb.conf

Al final del fichero creamos un bloque con la siguiente estructura obligatoria:

[Nombre_recurso]
    path = /[Carpeta_a_compartir]
    read only = no

[Nombre_recurso]: Es el nombre que aparecerá en Windows como carpeta.
path: Ruta completa de la carpeta a compartir en el servidor.
read only: Para permisos de escribir: no, o solo-lectura: yes.

Alojar una carpeta en un servidor Windows

1. Creación de usuarios y grupos:

Antes de asignar permisos, hay que crear los usuarios y grupos que sean necesarios.

Administrador de equipos → Usuarios y grupos locales → [Usuarios y Grupos] → Click derecho → Nuevo.
Asegurarse de que tenga la misma contraseña que la definida en el comando smbpasswd.

Desde la misma pestaña de Grupos hay que asignar a los usuarios creados dentro de su grupo correspondiente:
Grupo → Click derecho → Propiedades → Miembros → Agregar.


2. Asignar permisos:

Se puede asignar de forma que los permisos en red también se apliquen en los permisos locales (esto además quita la herencia de la carpeta):
Carpeta → Click derecho → Propiedades → Compartir → Botón "Compartir" → Añadir usuario/grupo → Asignar permisos.

También hay otra forma para asignar solo permisos de red:
Carpeta → Click derecho → Propiedades → Uso compartido avanzado → Botón "Permisos" → Agregar → Definir el usuario/grupo y asignar permisos.

Acceder a una carpeta Linux o Windows desde otro Linux

1. Explorar los recursos compartidos del servidor que puede montar un usuario:

smbclient -L //[IP_servidor] [Nombre_usuario]

2. Creación de una carpeta local:

mkdir /[Directorio_local_a_montar]

3. Instalar dependencias:

apt-get install -y cifs-utils

4. Montar la carpeta remota:

mount -t cifs -o username="Nombre_usuario_Windows",password="Contraseña" //[IP_servidor]/[Recurso] /[Directorio_local]
Explicación de los parámetros del comando: 
Nombre_usuario_Windows
 Usuario de la máquina Windows con permisos para acceder al recurso compartido. 
Contraseña
 Contraseña del usuario de la máquina Windows. 
//[IP_servidor]/[Recurso]
 Ruta del recurso compartido en Windows.
Nota: Linux utiliza solo las barras /. 
/[Directorio_local]
 Carpeta local donde se montará el recurso compartido.

4. Iniciar sesión con el usuario que montó la carpeta.

5. Comprobar que se puede acceder al recurso compartido.

Acceder a una carpeta de Windows desde otro Windows

1. Copiar la ruta de acceso de red en el servidor.

\\[Hostname_servidor_Windows]\[Recurso_compartido]

2. En el cliente iniciar sesión con un usuario con permisos de acceder al recurso.

3. En el explorador de ficheros buscar la ruta de acceso de red con el buscador.

4. Verificar si se puede acceder al contenido.

Acceder a una carpeta de Linux desde Windows

1. Iniciar sesión con un usuario que haya sido permitido explícitamente con el comando smbpasswd.

2. Listar los recursos compartidos:

En el Explorador de ficheros se tiene que buscar la barra de búsqueda:

\\[IP_servidor_Linux]

Aparecerá el recurso [Carpeta_a_compartir] y otra llamada [Nombre_usuario], que es la carpeta personal del usuario de Linux.

Nota: Si en vez de poner una carpeta con el nombre del usuario hay una que pone nobody significa que no se puede acceder al sistema con el usuario creado y por ello usa un usuario invitado que se llama nobody en el sistema Linux.
Si no deja acceder al recurso compartido con un usuario invitado hay que habilitar el parámetro guest ok = yes en el fichero /etc/samba/smb.conf.

Problema: Los usuarios se duplican en la máquina Linux y Windows.
Solución: Tener un servicio de usuarios en red como LDAP o Active Directory.

Montar una carpeta CIFS automáticamente en Linux

1. Editar el fichero /etc/fstab:

nano /etc/fstab

2. Añadir la siguiente línea:

Si no se quiere especificar credenciales, el sistema intentará montar el recurso como un usuario invitado, siempre que el servidor lo permita (guest ok = yes):

//[IP_servidor]/[Nombre_recurso]    /[Directorio_local]    cifs    [Opciones]   0   0

//[IP_servidor]/[Nombre_recurso]: Ruta del recurso compartido del servidor. Nota: Linux utiliza solo las barras /.
/[Directorio_local]: Carpeta local donde se montará el recurso compartido.

Opciones: 
defaults
 Si no se quiere especificar credenciales, el sistema intentará montar el recurso como un usuario invitado, siempre que el servidor lo permita (guest ok = yes). 
user
 Se puede permitir que un usuario, aunque no sea root, pueda montar carpetas con el comando mount. 
noauto
 Para que no se monte automáticamente la carpeta. 
username=[Nombre_usuario],password=[Contraseña]
 Se puede asignar las credenciales del usuario que tendrá acceso a este recurso compartido.

2.1. 🔨 problema de seguridad y su solución:

Problema de seguridad: /etc/fstab tiene el permiso local o=r--, indicando que todos los usuarios del sistema podrían leer las contraseñas que se indiquen en este fichero.

Primero hay que crear en cualquier ruta un fichero oculto de credenciales con el siguiente formato:

nano /[Ruta_fichero_credenciales]

Dentro de este fichero se debe indicar el usuario y contraseña:

username=[Nombre_usuario]
password=[Contraseña]

Luego guardamos el fichero y nos aseguramos que solo el usuario que monta la carpeta (root) pueda ver el fichero:

chown root:root /[Ruta_fichero_credenciales]
chmod 700 /[Ruta_fichero_credenciales]

Y por último hay que añadir en /etc/fstab la siguiente línea:

//[IP_servidor]/[Nombre_recurso]    /[Directorio_local]    cifs    credentials=/[Ruta_fichero_credenciales]   0   0

3. Comprobar que no haya errores en la configuración:

testparam

4. Montar la carpeta:

mount -a

Montar una carpeta SAMBA automáticamente en Windows

1. Iniciar sesión con un usuario autorizado para acceder al recurso compartido.

2. Agregar una unidad de red:

Para que se persistente hay que crear un punto de montaje en la siguiente ventana:
Explorador de ficheros → Este equipo → Pestaña "Equipo" → Conectar a unidad de red

En la ventana se debe asignar la letra de unidad de red donde se montará, además de la ruta del recurso compartido como - \\[IP_servidor]\Recurso.

Más parámetros en SAMBA

Ejemplo de un bloque completo en el fichero /etc/samba/smb.conf:

[Nombre_recurso]
    comment = Comentario del recurso compartido.
    path = /[Carpeta_a_compartir]
    browseable = no                # Por defecto: yes
    valid users = [Usuario1],[Usuario2],%S
    force user = [Usuario1]        # Por defecto: El usuario que inicia la conexión
    force group = [Grupo1]         # Por defecto: El grupo primario del usuario que inicia la conexión
    read only = no                 # Por defecto: yes
    read list = [Usuario1],[Usuario2]
    write list = [Usuario1],[Usuario2]
    create mask = 0700
    directory mask = 0700
    guest ok = no                 # Por defecto: no
    guest only = no               # Por defecto: no
    guest account = [Usuario1]    # Por defecto: nobody
    hide files = *.tmp
    hide dot files = yes
    follow symlinks = yes         # Por defecto: yes
    inherit permissions = no      # Por defecto: no
    wide links = no
    hosts allow = [PC1]           # Por defecto: (todos)
    hosts deny = [PC2]
Parámetros básicos: 
[Nombre_recurso]
 Es el nombre que aparecerá en Windows como carpeta. 
comment = ...
 Comentario opcional que no afecta en la configuración. 
path = ...
 Ruta completa de la carpeta a compartir en el servidor. 
browseable = yes / no
 No permite que se vea como recurso compartido así que solo se puede entrar por ruta de red como: \\[IP_servidor]_Linux\Recurso.
Lista de control de acceso: 
valid users = ...
 Permite definir usuarios que tengan acceso a la carpeta. Si se define %S se especifica que el nombre del recurso compartido también se incluya (solo es útil si el nombre de la carpeta es el de un usuario). 
force user = ...
 Asigna la propiedad de los ficheros a un usuario para evitar conflictos de permisos. 
force group = ...
 Asigna la propiedad de los ficheros a un grupo para evitar conflictos de permisos.
Parámetros de permisos básicos: 
read only = yes / no
 Para permisos de escribir: no, o solo-lectura: yes. 
read list = yes / no
 Lista de usuarios que solo pueden leer aunque read only = no. 
write list = yes / no
 Lista de usuarios que pueden escribir aunque read only = yes.
Parámetros de permisos avanzados: 
create mask = 0000
 Define los permisos por defecto para los ficheros nuevos que se creen en el recurso compartido. 
directory mask = 0000
 Define los permisos por defecto para los directorios nuevos que se creen dentro del recurso compartido.
Parámetros del usuario anónimo: 
guest ok = yes / no
 Para permisos que usuarios anónimos accedan: yes, o no: no. 
guest only = yes / no
 Para permisos que solo usuarios anónimos accedan: yes, o no: no. 
guest account = ...
 Se puede definir un usuario anónimo diferente al de por defecto.
Parámetros de ficheros: 
hide files = ...
 No enseña ficheros por coincidencias como por ejemplo *.tmp. 
hide dot files = yes / no
 No enseña ficheros que empiezen por un punto (ocultos).
Parámetros de enlaces simbólicos: 
follow symlinks = yes / no
 Permite seguir enlaces simbólicos dentro del recurso: yes, o no: no. 
inherit permissions = yes / no
 Permite heredar permisos de la carpeta padre en nuevos ficheros o sub-carpetas: yes, o no: no. 
wide links = yes / no
 Permite enlaces simbólicos que apuntan fuera del recurso: yes, o no: no.
Parámetros de hostnames: 
hosts allow = ...
 Lista de hostnames a los que se le permite acceder al recurso. 
hosts deny = ...
 Lista de hostnames a los que se le deniega acceder al recurso.

Por la mitad del fichero de configuraciones hay un bloque para las carpetas personales al cual se le pueden configurar los parámetros enseñados anteriormente:

[homes]

Parámetros de la sección [global] en SAMBA

Ejemplo de un bloque completo en el fichero /etc/samba/smb.conf:

[global]
    server role = standalone server # Por defecto: auto
    netbios name = [Hostname]
    workgroup = [Nombre_dominio]    # Por defecto: (nulo)
    security = [Nivel]              # Por defecto: user
    encrypt passwords = no          # Por defecto: no
    password server = [Contraseña]  # Por defecto: (nulo)
    map to guest = never            # Por defecto: never
    log level = 1
    log file = /[Ruta_fichero_logs]
Parámetros básicos: 
server role = ...
 standalone server: Servidor independiente que autentica usuarios.
member server: Servidor integrado en un dominio existente.
active directory domain controller: Controlador de dominio. 
netbios name = ...
 Nombre con el que el servidor Samba se identifica en la red mediante NetBIOS. 
workgroup = ...
 Nombre del grupo de trabajo o dominio al que pertenece el servidor Samba. 
netbios name = ...
 Nombre con el que el servidor Samba se identifica en la red mediante NetBIOS. 
security = ...
 Define el modo de autenticación que utilizará Samba (share, user, server, domain). Determina cómo se validan los usuarios al acceder a los recursos. 
encrypt passwords = yes / no
 Indica si las contraseñas se envían cifradas. Normalmente se establece en yes para compatibilidad con sistemas Windows modernos. 
password server = ...
 Servidor o lista de servidores encargados de autenticar a los usuarios. En modo domain, suele especificarse el controlador o controladores de dominio. 
map to guest = ...
 never: Nunca se asigna acceso como invitado.
bad user: Se convierte en invitado cuando el usuario no existe.
bad password: Se convierte en invitado cuando la contraseña es incorrecta.
bad uid: Se convierte en invitado cuando el usuario autenticado no puede asociarse a un UID válido en el sistema.
Logs: 
log level = ...
 Nivel de detalle de los registros de Samba. Cuanto mayor es el valor, más información se guarda en los logs. 
log file = ...
 Ruta y nombre del fichero donde Samba almacena los mensajes de registro y auditoría.

Monitorización

Para monitorizar las conexiones y bloqueos a recursos compartidos de tu sistema en tiempo real se puede ejecutar el siguiente comando:

smbstatus

Diagnóstico

Fallo de conectividad - Es importante comprobar el estado de los siguientes servicios:

systemctl status samba-ad-dc
systemctl status nmbd
systemctl status smbd

Fallo de autentificación - Otro problema puede ser que el usuario con el que se intenta acceder no esté añadido en smbpasswd:

smbpasswd -a [Nombre_usuario]

Acceso denegado - Hay que comprobar que los permisos sean los correctos:

ls -ld /[Ruta_al_recurso_montado]

Montaje de /etc/fstab - Hay que comprobar que la configuración del fichero de montaje sea correcto:

testparam
