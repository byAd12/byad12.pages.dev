BIND9

Servidor DNS en Linux

none

Instalación

En el servidor hay que instalar el servicio correspondiente:

apt-get update
apt-get install -y bind9

En el firewall permitiremos el paso del puerto 53 - UDP (DNS):

ufw allow 53

Probar si funciona

Primero miraremos si el servicio está encendido y sin errores:

service bind9 start
service bind9 status

Con el siguiente comando podremos verificar si hay algún error de sintaxis:

named-checkconf

Una vez configurado el servicio, podremos verificar si una zona está configurada en un archivo en específico:

named-checkzone adr.es /etc/bind/db.adr.es

Archivos importantes

/etc/bind/named.conf
 Archivo de configuración del servidor. 
/etc/bind/named.conf.local
 Archivo de zonas. 
/etc/bind/named.conf.default-zones
 Archivo de zonas por defecto - root. 
/etc/bind/named.conf.options
 Archivo de configuración del DNS.

Si hay problemas en el DNS

Verificaremos que los siguientes archivos no contengan registros DNS inválidos:

nano /etc/hosts
nano /etc/resolv.conf

Podemos probar a reiniciar los siguientes servicios:

systemctl restart networking
systemctl restart NetworkManager

Nslookup: Windows y Linux

El comando nslookup sirve para comprobar la configuración DNS de un dominio o IP según un registro específico.

Buscar los servidores DNS que gestionan un dominio específico:

# nslookup
> [IP_servidor_DNS] # El servidor que realizará la consulta
> set type=NS
> [Nombre_dominio].[TLD]

Buscar los servidores de correo para un dominio:

# nslookup
> [IP_servidor_DNS] # El servidor que realizará la consulta
> set type=MX
> [Nombre_dominio].[TLD]

Buscar los nombres asociados a una dirección IPv4:

# nslookup
> [IP_servidor_DNS] # El servidor que realizará la consulta
> set type=A
> [Nombre_dominio].[TLD]

Configurar el DNS como Reenviador: /etc/bind/named.conf.options

options {
directory "/var/cache/bind";

forwarders {
[IP_del_reenviador];
};

dnssec-validation no;
auth-nxdomain no;    # conform to RFC1035

listen-on { any; };
// listen-on-v6 { any; };
};

[IP_del_reenviador]: Es la dirección IPv4 del dispositivo al que reenviarán las peticiones DNS.
// listen-on-v6 { any; }: Es una línea comentada que se ignorará.

Crear una zona

En la carpeta /etc/bind crearemos un archivo (formato típico - db.Nombre_dominio.TLD) que contenga todos los registros DNS del dominio. Un ejemplo es el siguiente, que define los registros DNS de un dominio "adr.es":

$TTL    1D
adr.es. IN      SOA     dns1.adr.es.    administrador.adr.es    (
    1               ; Número de serie
    604800          ; Intervalo de actualización
    86400           ; Intervalo de reintento
    2419200         ; Expiración
    604800  )       ; TTL

adr.es. IN      NS      dns1.adr.es.
dns1    IN      A       192.168.0.230
www     IN      A       192.168.0.153
correo  IN      A       192.168.0.4
adr.es. IN      MX      1       correo
otra    IN      CNAME   iesjorgeguillen.es

En el archivo /etc/bind/named.conf.local añadiremos una nueva zona indicando el archivo creado en el paso anterior:

zone "[Nombre_dominio].[TLD]"{
type master;
file "/etc/bind/[Nombre_archivo_DB_dominio]";
};

Una vez configurado hay que comprobar con nslookup que los registros se han creado correctamente:

# nslookup
> 127.0.0.1
> set type=NS
> [Nombre_dominio].[TLD]

Crear una zona inversa

En la carpeta /etc/bind crearemos un archivo (formato típico - db.Dirección_red) que contenga todos los registros DNS de la zona inversa. Un ejemplo es el siguiente, que define los registros DNS de la zona 0.168.192.in-addr.arpa (192.168.0.0/24):

$TTL    1D
0.168.192.in-addr.arpa. IN      SOA     dns1.adr.es.    administrador.adr.es.   (
        1
        604800
        86400
        2419200
        10800   )

0.168.192.in-addr.arpa. IN      NS      dns1.adr.es.

230     IN      PTR     dns1.adr.es.
153     IN      PTR     www.adr.es.

En el archivo /etc/bind/named.conf.local añadiremos una nueva zona inversa indicando el archivo creado en el paso anterior:

zone "[Zona_inversa].in-addr.arpa"{
type master;
file "/etc/bind/db.192.168.0";
};

Una vez configurado hay que comprobar con nslookup que los registros se han creado correctamente:

# nslookup
> 127.0.0.1
> set type=NS
> [Zona_inversa].in-addr.arpa

Crear un servidor DNS secundario

En el servidor DNS1 editaremos el archivo /etc/bind/named.conf.local y añadiremos la siguiente configuración:

listen-on { [IP_servidor_secundario]; };
allow-transfer { [IP_servidor_secundario]; };
allow-query { [IP_servidor_secundario]; };

En el servidor DNS1 hay que añadir un nuevo registro DNS para el servidor secundario desde el archivo DB de la zona:

dns2	IN	A	[IP_servidor_secundario]

En el servidor DNS2 editaremos el archivo /etc/bind/named.conf.local y añadiremos la siguiente configuración:

zone "[Nombre_dominio].[TLD]"{
type slave;
masters{ [IP_servidor_principal]; };
file "/etc/bind/[Nombre_archivo_DB_dominio]";
};

DNS

Configuración en Windows

Configurar

Pasos:


  1. Configurar una IP estática
  2. Administrador del Servidor > Agregar rol llamado "Servidor DNS" > Instalar
  3. Administrador del Servidor > Herramientas > DNS > [Nombre_Servidor] > Reenviadores > Editar > Añadir la IP del servidor DNS que actuará como reenviador

Es necesario especificar con un registro A donde está el servidor DNS primario y crearle un registro NS.

Para configurar registros de tipo A:

Administrador del Servidor > Herramientas > DNS > [Nombre_Servidor] > Zonas de Búsqueda directa > Click derecho > Registro A.

Para configurar registros de tipo MX:

Lo mismo que al crear registros de tipo A pero no se debe de asignar un nombre al registro.
