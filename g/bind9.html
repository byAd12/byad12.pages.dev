BIND9

Servidor DNS en Linux

none

1. Instalación

En el servidor hay que instalar el servicio correspondiente y sus dependencias:

apt-get update
apt-get install -y bind9 dnsutils

2. Configuración del firewall

En el firewall se debe permitir el tráfico del puerto 53 - UDP (DNS):

ufw allow 53

Ficheros importantes

/etc/bind/named.conf
 Fichero de configuración del servidor. 
/etc/bind/named.conf.local
 Fichero de zonas. 
/etc/bind/named.conf.default-zones
 Fichero de zonas por defecto - root. 
/etc/bind/named.conf.options
 Fichero de configuración del DNS.

3. Configuración del Servidor DNS

3.1. Crear una zona de búsqueda directa

En la carpeta /etc/bind hay que crear un fichero (formato típico - db.Nombre_dominio.TLD) que contenga todos los registros DNS del dominio. Un ejemplo es el siguiente, donde se definen los registros DNS de un dominio llamado adr.es:

$TTL    1D
adr.es. IN      SOA     dns1.adr.es.    administrador.adr.es    (
    1               ; Número de serie
    604800          ; Intervalo de actualización
    86400           ; Intervalo de reintento
    2419200         ; Expiración
    604800  )       ; TTL

adr.es. IN      NS      dns1.adr.es.
dns1    IN      A       192.168.0.230
www     IN      A       192.168.0.153
correo  IN      A       192.168.0.4
adr.es. IN      MX      1       correo
otra    IN      CNAME   iesjorgeguillen.es

En el fichero /etc/bind/named.conf.local se debe añadir una nueva zona indicando el fichero creado en el paso anterior:

zone "[Nombre_dominio].[TLD]"{
type master;
file "/etc/bind/[Nombre_fichero_DB_dominio]";
};

Una vez configurado hay que comprobar con nslookup que los registros se han creado correctamente:

# nslookup
> server 127.0.0.1
> set type=NS
> [Nombre_dominio].[TLD]

3.2. Crear una zona de búsqueda inversa

En la carpeta /etc/bind hay que crear un fichero (formato típico - db.Dirección_red) que contenga todos los registros DNS de la zona inversa. Un ejemplo es el siguiente, que define los registros DNS de la zona 0.168.192.in-addr.arpa (192.168.0.0/24):

$TTL    1D
0.168.192.in-addr.arpa. IN      SOA     dns1.adr.es.    administrador.adr.es.   (
        1
        604800
        86400
        2419200
        10800   )

0.168.192.in-addr.arpa. IN      NS      dns1.adr.es.

230     IN      PTR     dns1.adr.es.
153     IN      PTR     www.adr.es.

En el fichero /etc/bind/named.conf.local se debe añadir una nueva zona inversa indicando el fichero creado en el paso anterior:

zone "[Zona_inversa].in-addr.arpa"{
type master;
file "/etc/bind/db.192.168.0";
};

Una vez configurado hay que comprobar con nslookup que los registros se han creado correctamente:

# nslookup
> server 127.0.0.1
> set type=NS
> [Zona_inversa].in-addr.arpa

2.3. Configurarlo como servidor de reenvío

Primero hay que editar el siguiente fichero:

nano /etc/bind/named.conf.options

Dentro del fichero se debe configurar lo siguiente:

options {
directory "/var/cache/bind";

forwarders {
[IP_del_reenviador];
};

dnssec-validation no;
auth-nxdomain no;    # conform to RFC1035

listen-on { any; };
// listen-on-v6 { any; };
};

IP_del_reenviador: Es la dirección IPv4 del dispositivo al que reenviarán las peticiones DNS.
listen-on-v6: Es una línea comentada que se ignorará.

4. Comprobación del funcionamiento

Primero hay que mirar si el servicio está encendido y sin errores:

service bind9 start
service bind9 status

Con el siguiente comando se puede verificar si hay algún error de sintaxis:

named-checkconf

Una vez configurado el servicio, se puede verificar si una zona está configurada en un fichero en específico:

named-checkzone [Nombre_dominio].[TLD] /etc/bind/[Nombre_fichero_zona]

5. Si el cliente tiene problemas con el DNS

Primero se verifica que los siguientes ficheros no contengan registros DNS inválidos:

nano /etc/hosts
nano /etc/resolv.conf

Se puede probar a reiniciar los siguientes servicios:

systemctl restart networking
systemctl restart NetworkManager

Adicional: Configurar un servidor DNS secundario

Servidor primario: DNS1; Servidor secundario: DNS2.

En el servidor DNS1 hay que editar el fichero /etc/bind/named.conf.local y añadir la siguiente configuración:

listen-on { [IP_servidor_secundario]; };
allow-transfer { [IP_servidor_secundario]; };
allow-query { [IP_servidor_secundario]; };

En el servidor DNS1 hay que añadir un nuevo registro DNS para el servidor secundario desde el fichero DB de la zona:

dns2	IN	A	[IP_servidor_secundario]

En el servidor DNS2 hay que editar el fichero /etc/bind/named.conf.local y añadir la siguiente configuración:

zone "[Nombre_dominio].[TLD]"{
type slave;
masters{ [IP_servidor_principal]; };
file "/etc/bind/[Nombre_fichero_DB_dominio]";
};

Comando: dig

El comando dig permite realizar las mismas consultas DNS de un nombre de dominio o IP que el comando nslookup pero con más opciones:

dig (Tipo_registro_DNS) [IP/Registro_DNS] (Opciones)

Tipo_registro_DNS: Es el tipo de registro DNS que se quiere buscar. Por defecto es el registro "A".
Una opción puede ser +short, que resume la salida para dar directamente el nombre de dominio o IP que se busca.

Un ejemplo de uso es el siguiente, donde se buscan los servidores NS de un dominio y luego se averigua sus direcciones IPs:

# dig NS byad12.pages.dev +short
toby.ns.cloudflare.com.
wally.ns.cloudflare.com.
# dig toby.ns.cloudflare.com +short
108.162.193.239
172.64.33.239
173.245.59.239

Se puede hacer lo mismo con los servidores MX del dominio y con otros registros.

Para averiguar la dirección de email del administrador del dominio se puede mirar directamente en el registro SOA:

# dig SOA xunta.gal +short
a1-15.akam.net. sistemas.xunta.es. 2018123161 86400 7200 2592000 172800

En este caso se puede ver que "sistemas.xunta.es" es la dirección de email. Solo hay que cambiar el primer punto por un "@": sistemas@xunta.es.

Comando: nslookup

El comando nslookup permite comprobar la configuración DNS de un dominio:

nslookup (-type=[Tipo_registro_DNS]) (-port=[Puerto_servidor_DNS]) [Nombre_dominio].[TLD] ([IP_servidor_DNS])

-type: Puede ser un registro A, AAAA, MX, SOA, NS, CNAME, PTR, SRV, ...
Puerto_servidor_DNS: El puerto del servidor DNS que resolverá la consulta.
IP_servidor_DNS: La IP del servidor DNS que resolverá la consulta.

También permite hacer consultas DNS inversas para ver el nombre de dominio asignado a una IP:

nslookup [IP]

También se puede ejecutar el comando en varias líneas:

# nslookup
> server [IP_servidor_DNS]
> set type=[Tipo_registro_DNS]
> [Nombre_dominio].[TLD]

Comando: whois

El comando whois de Linux permite ver información sobre un dominio o una IP, quién registró el dominio, información de contacto, servidores NS, fecha de creación y expiración y otra información.

Para usar el comando primero se debe instalar mediante APT:

apt-get install -y whois

Sintaxis del comando:

whois [IP/Registro_DNS]

Como realizar búsquedas DNS inversas

El servicio web viewdns.info permite realizar búsquedas de nombres de dominios relacionados a una misma IP pública.

Mediante línea de comandos se puede realizar búsquedas DNS inversas usando el comando dig:

dig -x [IP_servidor] +short

Configuración en Windows

Configurar

Pasos:


  1. Configurar una IP estática
  2. Administrador del Servidor > Agregar un rol llamado "Servidor DNS" > Instalar
  3. Administrador del Servidor > Herramientas > DNS > [Nombre_servidor] > Reenviadores > Editar > Añadir la IP del servidor DNS que actuará como reenviador

Es necesario especificar con un registro A donde está el servidor DNS primario y crearle un registro NS.

Para configurar registros de tipo A:

Administrador del Servidor > Herramientas > DNS > [Nombre_servidor] > Zonas de Búsqueda directa > Click derecho > Registro A.

Para configurar registros de tipo MX:

Lo mismo que al crear registros de tipo A pero no se debe de asignar un nombre al registro.
