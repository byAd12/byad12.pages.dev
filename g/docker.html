Imágenes

Gestionar imágenes

Descargar una imagen desde el repositorio hub.docker.com sin necesidad de autenticarse:

docker pull [Imagen]:(Versión)

Si no se especifica la versión de la imagen a ejecutar, será la última disponible (latest).

Crear un docker sin iniciarlo:

docker create [Imagen]:(Versión)

Ver todas las imágenes descargadas o creadas en el sistema local:

docker image ls

Inspeccionar una imagen descargada específica:

docker image inspect [Imagen]:(Versión)

Eliminar una imagen:

docker image rm [Imagen]:(Versión)

Nota: no debe haber ningún docker creado que esté asociado con la imagen a eliminar.

Crear una imagen a partir de un docker

Primero hay que crear una cuenta gratuita en hub.docker.com para poder subir públicamente las imágenes que se vayan a crear.

Ahora hay que iniciar sesión en la terminal con las credenciales que hayamos definido al crear la cuenta:

docker login -u [Nombre_usuario]

Con el contenedor listo, se debe crear un commit indicando el nombre del contenedor y el nombre con el que se guardará:

docker commit [Nombre/ID_Contenedor] [Nombre_usuario]/[Nombre_nueva_imagen]

Para evitar corromper los datos se recomienda detener el docker previamente.

Se puede verificar con el siguiente comando que la imagen aparece en el sistema local:

docker image ls

Para subir la nueva imagen al repositorio hay que ejecutar un push:

docker push [Nombre_usuario]/[Nombre_nueva_imagen]

Nota: Hay que tener en cuenta que los datos deberían almacenarse en volúmenes y no en el propio docker → el docker debería ser lo más ligero posible, permitiendo así actualizar o migrar la versión de un contenedor sin necesidad de copiar los datos de nuevo.

Cliente Docker CLI

Información de la aplicación

Ver la versión del cliente de Docker:

docker --version

Ver la versión del cliente de Docker con mayor detalle:

docker version

Ver la información del cliente de Docker:

docker info

Ver registros

Ver todos los eventos de los contenedores:

docker events

Ver los registros de un contenedor en tiempo real:

docker logs -f [Nombre/ID_Contenedor]

Inspeccionar la configuración y estado de un contenedor o imagen:

docker inspect --format=(Formato) [Contenedor/Imagen]

El parámetro --format es opcional. Sirve para extraer un dato específico de una imagen o un contenedor, como puede ser el {{.Id}}, {{.State.Status}}, ...

Contenedores

Crear un docker a partir de una imagen

El comando docker run crea un contenedor nuevo a partir de una imagen. Una vez creado se iniciará automáticamente: 

docker run (Parámetros) [Imagen]:(Versión) (Comando)

Si la imagen especificada no se descargó previamente, el sistema descargará la versión latest a no ser que se especifique otra versión.

Parámetros generales: 
-d
 Ejecuta el contenedor en segundo plano. 
-v [Ruta_en_sistema_local]:[Ruta_en_contenedor]
 Persistencia de ficheros - Sirve para enlazar una carpeta del contenedor con una carpeta local para que los ficheros permanezcan incluso si se elimina el contenedor. 
-e [Variable_entorno]=[Valor]
 Modifica una variable de entorno (ej. PUID). 
-h [Hostname]
 Especifica el hostname que tendrá el contenedor internamente. 
--name [Nombre]
 Asigna un nombre al contenedor para poder identificarlo de otros contenedores. 
--restart unless-stopped
 Indica que se quiere ejecutar el contenedor persistentemente hasta que se detenga manualmente. 
--rm
 Indica que se debe eliminar el contenedor al finalizar la tarea o cuando se detenga manualmente.
Parámetros - Limitación de recursos: 
--cpus [Cantidad_CPUs]
 Limita los núcleos de la CPU que el contenedor puede utilizar como máximo (número decimal). 
-m [Cantidad_RAM][Unidad]
--memory [Cantidad_RAM][Unidad]
 Ambos parámetros realizan la misma función:
Limitan la cantidad de RAM que el contenedor puede utilizar como máximo. Ejemplos: "512M" (MiB), "1G" (GiB).
Parámetros - Redirección de puertos: 
-P
 Se redireccionan automáticamente todos los puertos abiertos que tenga el docker en ejecución y le asigna un puerto libre del host. 
-p [Puerto_local]:[Puerto_contenedor]
 Redirecciona el puerto local del host hacia el puerto interno del contenedor. 
-p [IP_local]:[Puerto_local]:[Puerto_contenedor]
 También se puede especificar la IP del sistema local del host.
Se pueden redireccionar varios puertos a la vez; para ello, hay que repetir el parámetro -p por cada puerto a redireccionar.
Parámetros - Modo de red: 
--network bridge
 Modo bridge (Modo por defecto): Con este parámetro el contenedor tendrá una IP propia de la red interna y se permitirá el mapeo de puertos. El servidor DNS será el mismo servidor que utiliza el host. 
--network host
 Modo host: Con este parámetro el docker tendrá la misma IP del host y los puertos se exponen sin necesidad de utilizar el parámetro -p.
Parámetros - Otras configuraciones de red: 
--dns=[IP_servidor_DNS]
 Con este parámetro se indica manualmente el servidor DNS para el contenedor. Para añadir un servidor secundario se debe duplicar este parámetro. 
--add-host=[Nombre_dominio]:[IP]
 Con este parámetro se indica un nuevo registro DNS interno en el fichero /etc/hosts. Para añadir otro registro se debe duplicar este parámetro.
Parámetros - Sobreescribir la tarea principal: 
docker run [Imagen]:(Versión) [Comando]
 Si por ejemplo se va a ejecutar un docker nginx, se puede definir que se ejecute otro proceso diferente y cuando finalice, se detendrá el contenedor.
Parámetros - Abrir una terminal al ejecutar el contenedor: 
docker run -it [Imagen]:(Versión) (bash|sh)
 Con el parámetro -i se mantiene abierta la entrada estándar STDIN para poder enviar comandos al contenedor. El parámetro -t permite que en ese flujo de datos aparezcan colores y se pueda usar el tabulador.

Con (bash|sh) se sobrescribe la tarea por defecto para forzar la apertura de una consola interactiva bash o sh.

Para abrir la terminal en un contenedor que ya se está ejecutando, mire la sección "Abrir una terminal en un contenedor iniciado".

El siguiente comando permite modificar los límites de recursos y políticas de reinicio de un contenedor ya creado:

docker update [Parámetros] [Nombre/ID_Contenedor]

Listar contenedores

Para ver los contenedores en ejecución:

docker ps

Ver todos los contenedores en ejecución y detenidos:

docker ps -a

Los 2 comandos anteriores muestran el ID, nombre, tiempo de ejecución y tiempo de creación de cada contenedor.

Gestionar la ejecución de un contenedor

Iniciar un contenedor:

docker start [Nombre/ID_Contenedor]

Detener un contenedor:

docker stop [Nombre/ID_Contenedor]

Pausar o reanudar un contenedor:

docker pause [Nombre/ID_Contenedor]
docker unpause [Nombre/ID_Contenedor]

También se puede realizar cualquier acción sobre todos los contenedores del sistema con el siguiente comando:

docker [Acción] $(docker ps -a -q)

La acción puede ser start, stop, rm, pause, unpause, etc.
Para aplicarlo solo a los contenedores en ejecución hay que quitar el parámetro -a.

Eliminar un contenedor

Para eliminar un contenedor primero se debe detener manualmente:

docker stop [Nombre/ID_Contenedor]
docker rm [Nombre/ID_Contenedor]

O también se puede forzar la eliminación sin necesidad de detenerlo manualmente:

docker rm -f [Nombre/ID_Contenedor]

Copiar ficheros entre el host y el contenedor

Cómo copiar ficheros internos del contenedor al host:

docker cp [Nombre/ID_Contenedor]:[Ruta_en_contenedor] [Ruta_en_sistema_local]

[Nombre/ID_Contenedor]: Nombre del contenedor específico que contiene los ficheros a copiar.
[Ruta_en_contenedor]: Ruta interna del contenedor que contiene el fichero o los ficheros a copiar.
[Ruta_en_sistema_local]: Ruta local del host donde se copiarán los ficheros.

Copiar ficheros del host al interior del contenedor:

docker cp [Ruta_en_sistema_local] [Nombre/ID_Contenedor]:[Ruta_en_contenedor]

[Ruta_en_sistema_local]: Ruta local del host que contiene los fichero(s) a copiar.
[Nombre/ID_Contenedor]: Nombre o ID del contenedor al que se copiarán los ficheros.
[Ruta_en_contenedor]: Ruta local del contenedor donde se copiarán los ficheros.

Abrir una terminal en un contenedor iniciado

En una terminal se debe ejecutar el siguiente comando para iniciar una sesión de terminal en un contenedor existente e iniciado:

docker exec -it [Nombre/ID_Contenedor] /bin/[bash|sh]

-i: Modo interactivo.
-t: Proporciona una interfaz de línea de comandos.
[Nombre/ID_Contenedor]: El nombre o ID del contenedor al que se quiere acceder.
[bash|sh]: Abre una sesión de bash o shell.

Volúmenes

Un volumen permite que los datos de una ruta en el contenedor permanezcan almacenados en el host incluso después de que el contenedor haya sido eliminado.

Ver todos los volúmenes del sistema:

docker volume ls

Crear un nuevo volumen:

docker volume create [Nombre_volumen]

Eliminar un volumen existente:

docker volume rm [Nombre_volumen]

Para montar un volumen existente en un contenedor se puede hacer de 2 maneras:

docker run -d -v [Nombre_volumen]:[Ruta_en_contenedor] [Imagen]:(Versión)
docker run -d --mount type=volume,source=[Nombre_volumen],target=[Ruta_en_contenedor] [Imagen]:(Versión)

Todos los datos que haya en source se cargarán automáticamente en target. Sin embargo, si el volumen está vacío y target contiene datos, estos se copiarán automáticamente a source. Se permite crear datos en el volumen desde el host y el contenedor a la vez.
Si el volumen no existe, se creará automáticamente.

Los datos del volumen se almacenan localmente en el sistema del host en la ruta: /var/lib/docker/volumes/[Nombre_volumen]/_data.

Gestión de redes

Comando para ver las redes y de qué tipos son para cada contenedor:

docker network ls

Comando para crear una nueva red:

docker network create --driver (Tipo_de_red) --subnet (Dirección_red)/(Máscara_CIDR) --gateway (IP_default_gateway) [Nombre_red]

--driver, --subnet y --gateway son opcionales. Creará una interfaz en el host.

--driver: Es el modo de red a seleccionar como bridge, none, host, ...

Eliminar una red tipo bridge:

docker network rm [Nombre_red]

Conectar un contenedor que ya existe a una red:

docker network connect [Nombre_red] [Nombre/ID_Contenedor]

Para quitarlo de la red solo hay que cambiar connect por disconnect.

Ejemplos

Contenedor "httpd"

Añadir un volumen a un contenedor con httpd y crear una página HTML:

docker volume create volumen_httpd_prueba
docker run -p 8080:80 --name httpd_prueba -v volumen_httpd_prueba:/usr/local/apache2/htdocs -d httpd

Ahora en la máquina en la que se ejecute el docker (anfitrión) hay que acceder al volumen y añadir un nuevo fichero HTML:

nano /var/lib/docker/volumes/volumen_httpd_prueba/_data/index.html

Para visualizar la página web hay que acceder a la URL http://[IP_máquina_anfitrión]:8080.

Contenedor "heimdall"

Sirve para organizar aplicaciones web en un solo lugar:

docker run --name heimdall -e PUID=1000 -e PGID=1000 -e TZ=america/new_york -p 9998:80 -p 9997:443 -v /home/usuario/Descargas/docker_adr:/config --restart unless-stopped linuxserver/heimdall

Para visualizar la página web hay que acceder a la URL http://[IP_máquina_anfitrión]:9998.
