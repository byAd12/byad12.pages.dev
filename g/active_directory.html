Configurar un sistema Linux como controlador de dominio

Además de crear servidores Windows para que controlen Active Directory, se puede configurar un servidor Linux para que actúe como controlador de dominio con las mismas funcionalidades pero sin la necesidad de adquirir licencias.


1. Primero hay que asignar al servidor una dirección IPv4 estática. Se puede mirar la dirección IP del sistema con:

ip a

2. Hay que asignar un hostname al cliente definiendo su dominio completo:

hostnamectl set-hostname [Hostname_servidor_Linux].[Nombre_dominio].[TLD]

Para verificar los cambios se podría mirar que el siguiente fichero contenga el hostname actualizado:

cat /etc/hostname

3. Ahora se debe configurar un registro DNS interno para cada equipo de la red en el fichero /etc/hosts.

3.1. Primero se debe eliminar los registros que contengan el hostname antiguo del servidor:

127.0.0.1     [Hostname_servidor_antiguo_Linux]

3.2. Luego se debe añadir un registro que apunte a cada IP de los equipos de la red mediante su hostname y dominio:

[IP_servidor_Linux]     [Hostname_servidor_Linux].[Nombre_dominio].[TLD]     [Hostname_servidor_Linux]
<IP_Cliente_1>     [Hostname_cliente1].[Nombre_dominio].[TLD]     [Hostname_cliente1]
...

4. Ahora hay que instalar los paquetes necesarios:

apt-get install -y samba winbind

5. Hay que detener y deshabilitar los siguientes servicios:

systemctl stop samba-ad-dc smbd nmbd winbind
systemctl disable samba-ad-dc smbd nmbd winbind

6. Antes de configurar SAMBA hay que crear una copia de seguridad de su fichero de configuración:

mv /etc/samba/smb.conf /etc/samba/smb.conf.bak

7. Con el siguiente comando interactivo hay que generar una configuración de SAMBA:

samba-tool domain provision --use-rfc2307 --interactive
  • "Realm" → el nombre de dominio en mayúsculas.
  • "Domain" → el nombre de dominio sin el TLD y en mayúsculas.
  • "Server Role" → dc (Domain Controller).
  • "DNS Backend" → SAMBA_INTERNAL.
  • "DNS Forwarders" → la IP de un servidor DNS local o de Internet (1.1.1.1, ...).
  • Luego pedirá la contraseña del usuario Administrador y empezará con el proceso de configuración.

8. Ahora hay que verificar que la configuración sea la correcta:

cat /etc/samba/smb.conf

9. Para poder resolver correctamente consultas DNS hay que eliminar del fichero /etc/nsswitch.conf la sección mdns4_minimal [NOTFOUND=return] de una línea llamada hosts. Esa línea debería quedar con este contenido: 

hosts: files dns myhostname

10. Por último hay que habilitar e iniciar todos los servicios deshabilitados en el paso 5:

systemctl start samba-ad-dc smbd nmbd winbind
systemctl enable samba-ad-dc smbd nmbd winbind

Es importante que todos esos servicios estén activos para poder unirse al dominio. Si algo falla, se debe mirar el estado de cada servicio.


En la siguiente sección se puede ver la administración del servidor mediante línea de comandos.

Importante: El usuario administrador del dominio se llama administrator (en inglés).

Administrar un sistema Linux como controlador de dominio

Gestión del dominio: 
samba-tool domain info 127.0.0.1
 Ver información del dominio. 
samba-tool domain provision --help
 Comprobar estado del Controlador de Dominio.
Gestión de equipos del dominio: 
samba-tool computer list
 Subdominio completo del servidor. 
samba-tool computer show [Hostname]
 Mostar información detallada de un equipo del dominio. 
samba-tool computer delete [Hostname]
 Eliminar equipo del dominio.
Gestión de usuarios: 
samba-tool user list
 Listar todos los usuarios del dominio. 
samba-tool user add [Nombre_usuario]
 Crear un nuevo usuario. 
samba-tool user delete [Nombre_usuario]
 Eliminar un usuario existente. 
samba-tool user setpassword [Nombre_usuario]
 Cambiar la contraseña de un usuario existente. 
samba-tool user show [Nombre_usuario]
 Mirar información detallada de un usuario.
Gestión de grupos: 
samba-tool group list
 Listar todos los grupos del dominio. 
samba-tool group listmembers [Nombre_grupo]
 Listar los miembros de un grupo. 
samba-tool group add [Nombre_grupo]
 Crear un nuevo grupo. 
samba-tool group delete [Nombre_grupo]
 Eliminar un grupo existente. 
samba-tool group addmembers [Nombre_grupo] [Nombre_usuario]
 Añadir un usuario a un grupo.
Gestión de unidades organizativas (OU): 
samba-tool ou list
 Listar todas las unidades organizativas del dominio. 
samba-tool ou create "OU=[Nombre_unidad_organizativa],DC=[Nombre_dominio],DC=[TLD]"
 Crear una nueva unidad organizativa, como "ou=text,dc=iso,dc=local". 
samba-tool ou delete "OU=[Nombre_unidad_organizativa],DC=[Nombre_dominio],DC=[TLD]"
 Eliminar una unidad organizativa, como "ou=text,dc=iso,dc=local".

Scripts de inicio de sesión desde un controlador de dominio Linux

Esta sección muestra como definir scripts de inicio de sesión para usuarios en equipos Windows. En equipos Linux es mejor usar PAM.


1. Para configurarlo, primero añadir al final del fichero /etc/samba/smb.conf la siguiente sección, pero definiendo el nombre del dominio correctamente:

[netlogon]
    path = /var/lib/samba/sysvol/[Nombre_dominio].[TLD]/scripts

Dentro de esa ruta se podrán guardar los scripts .bat que se ejecutarán en el cliente Windows. La ruta al recurso compartido es:

\\[Hostname_servidor_Linux]\netlogon

Ahora se puede asociar el script al usuario mediante un equipo Windows con RSAT o con el siguiente comando en el servidor:

samba-tool user setprofile [Nombre_usuario] --script-path [Nombre_script].bat

El script es una ruta relativa desde la ruta de sysvol configurada anteriormente.

En un equipo Windows con RSAT se puede configurar desde: WIN + R → dsa.msc → Usuario → Propiedades → Profile → Logon script.

SAMBA: Unir un cliente Linux a un controlador de dominio

Con los siguientes pasos en un cliente Linux se puede meter el equipo en un dominio creado por un controlador de dominio, tanto si es un servidor Linux o Windows:


1. Primero hay que eliminar del fichero /etc/nsswitch.conf la sección mdns4_minimal [NOTFOUND=return] de una línea llamada hosts. Esa línea debería quedar con este contenido: 

hosts: files dns myhostname

Esto se debe realizar porque los dominios .local se intentan resolver por mDNS, y eso impide que Linux consulte al DNS de Active Directory.


2. Para permitir el inicio de sesión con usuarios del dominio se debe añadir en el fichero /etc/nsswitch.conf la palabra winbind al final de las líneas passwd y group:

passwd:         files systemd winbind
group:          files systemd winbind

3. Hay que poner como DNS la IP del servidor de Active Directory. Verificación:

cat /etc/resolv.conf
ping [Hostname_servidor].[Nombre_dominio].[TLD]

Si no se especifica el dominio completo no funcionará ya que no hay un dominio de búsqueda configurado para añadir ese dominio automáticamente.


4. Ahora hay que configurar el dominio de búsqueda, que permite contactar a un subdominio sin especificar el dominio completo, mediante el siguiente comando:

nm-connection-editor

Importante → Hay que ejecutar este comando con un usuario diferente a root ya que este no tiene permisos de modificar la interfaz gráfica.

4.1. Hay que ir a "Ajustes de IPv4" y añadir search [Nombre_dominio].[TLD] en la sección de "Dominios de búsqueda".

4.2. Para verificar que funciona, hay que realizar una consulta ICMP a un subdominio sin especificar el dominio completo:

ping [Subdominio_servidor]

Alternativa → También se podría hacer añadiendo la línea search [Nombre_dominio].[TLD] en el fichero /etc/resolv.conf, pero al reiniciar el sistema no se aplicaría el cambio ya que el servicio Networking regenera su configuración en cada inicio del sistema.


5. Hay que asignar un hostname al cliente definiendo su dominio completo:

hostnamectl set-hostname [Hostname_cliente_Linux].[Nombre_dominio].[TLD]

Para verificar los cambios se podría mirar que el siguiente fichero contenga el hostname actualizado:

cat /etc/hostname

6. Ahora se debe configurar un registro DNS interno para el propio cliente en el fichero /etc/hosts:

6.1. Primero hay que eliminar los registros que contengan el hostname antiguo del cliente:

127.0.0.1     [Hostname_cliente_antiguo]

6.2. Luego hay que añadir un registro que apunte al propio cliente mediante su hostname y dominio:

[IP_cliente]     [Hostname_cliente].[Nombre_dominio].[TLD]     [Hostname_cliente]

7. Ahora hay que instalar los paquetes necesarios:

apt-get update
apt-get install -y samba winbind krb5-user libnss-winbind libpam-winbind

En caso de que pida el nombre del reino de KRB5 hay que poner el nombre del dominio completo.

Para verificar que se instalaron con éxito se puede consultar el siguiente fichero y verificar que default_realm es el nombre de dominio en mayúsculas:

cat /etc/krb5.conf

8. A continuación hay que modificar la sección [GLOBAL] de SAMBA, situado en el fichero /etc/samba/smb.conf:

8.1. Hay que asignar como valor de workgroup el nombre de dominio en mayúsculas y sin el TLD (ej. CICLO → ciclo.local):

workgroup = [Dominio_sin_TLD_y_en_mayúsculas]

8.2. Hay que añadir una nueva línea indicando que el valor de realm sea el nombre de dominio completo (ej. ciclo.local):

realm = [Nombre_dominio].[TLD]

8.3. Hay que configurar server role para definir que el equipo actuará como miembro y no como servidor:

server role = member server

8.4. Ahora hay que añadir el siguiente bloque de configuración para que SAMBA pueda listar los usuarios con winbind:

    idmap config * :              backend = tdb
    idmap config * :              range   = 3000-7999
    template shell = /bin/bash
    template homedir = /home/%D/%u
    password server = *
    winbind use default domain = yes
    winbind enum users = yes
    winbind enum groups = yes
Explicación de la configuración: 
idmap config * : backend = tdb
 Indica que "tdb" (Trivial DataBase) será la base de datos. 
idmap config * : range = 3000-7999
 Es el rango de UIDs para los usuarios de Windows que se metan al dominio. 
template shell = /bin/bash
 La terminal por defecto que tendrá en usuario que se cree desde Windows. 
template homedir = /home/%D/%u
 La ruta de la carpeta personal para los usuarios. Se crearán las carpetas con los nombres de usuario %u dentro una subcarpeta de /home cuyo nombre es el nombre de dominio %D. 
password server = *
 Se utilizará automáticamente cualquier controlador de dominio disponible. 
winbind use default domain = yes
 Para evitar poner el nombre de usuario como CICLO\user o user@dominio al iniciar sesión. 
winbind enum users = yes
 Permite listar todos los usuarios del dominio. 
winbind enum groups = yes
 Permite listar todos los grupos del dominio.

9. Para unir el cliente al dominio sigue los siguientes pasos:

9.1. Comprueba que el cliente sea capaz de listar la información del dominio:

net ads info
  • En caso de que de un error, hay que verificar que el paso 7 se realizó correctamente.

9.2. Hay que intentar unir el cliente al dominio usando las credenciales del usuario Administrador de Windows Server:

net ads join -U Administrador
  • Si da un error en este paso es por realizar incorrectamente el paso 5.
  • Si hay un error de DNS, es porque ya hubo otro cliente con el mismo nombre y dominio en el servidor o que no se configuró el paso 4 correctamente.
  • Si permite unirse al dominio, se puede ver el equipo en la sección Computers del servidor de Windows.

9.3. Una vez se haya unido el cliente al dominio, este debería de ver el Identificador de Seguridad (SID) único del dominio:

net ads info

9.4. Ahora hay que reiniciar el servicio de winbind para que sea capaz de listar los usuarios de Windows:

systemctl restart winbind.service
wbinfo -u
  • Con el comando id USUARIO se puede ver la información de un usuario en concreto.
  • También se debería poder iniciar sesión con cualquier usuario de Windows en el sistema local.
  • Gracias al servicio libpam-winbind se puede iniciar sesión ya que este modifica el fichero /etc/pam.d/common-auth para que poder comprobar las contraseñas de Windows.

9.5. Al iniciar sesión con un usuario de Windows aparecerá un error de que no se puede crear la carpeta personal. Para solucionarlo hay que marcar la opción "Create home directory on login" en el asistente que aparecerá al ejecutar el siguiente comando: 

pam_auth_update

9.6. Por último, hay que comprobar que se aplicó correctamente la configuración asignada en smb.conf (UID, carpeta /home y shell) al usuario de Windows:

cat /etc/passwd | grep [Nombre_usuario_windows]

Montar en un cliente Linux una carpeta del controlador de dominio

Este proceso equivale a la "Carpeta particular" o "Unidad de red" en Windows. Permite que el usuario acceda a sus ficheros alojados en el servidor desde el cliente Linux, definiendo un punto de montaje local para la carpeta compartida del dominio.


1. Primero hay que instalar los paquetes necesarios:

apt-get update
apt-get install -y libpam-mount cifs-utils

2. Ahora hay que editar el fichero de configuración de pam_mount - /etc/security/pam_mount.conf.xml:

2.1. Primero hay que cambiar el siguiente parámetro de 0 a 1 para que las carpetas de destino se creen automáticamente:

<mkmountpoint enable="1" />

2.2. Justo después de un comentario "Volume definitions" hay que añadir una nueva etiqueta volume por cada carpeta a montar:

<!-- Volume definitions -->

<volume
    fstype="cifs"
    server="hostname_servidor.dominio.tld"
    path="nombre_recurso_compartido"
    mountpoint="~/ruta_montar_localmente"
    sgrp="nombre_grupo_permitido"
/>
Explicación de la configuración: 
fstype=""
 Tipo de sistema de ficheros de la carpeta a montar. 
server=""
 Subdominio completo del servidor. 
path=""
 Nombre del recurso compartido del servidor. 
mountpoint=""
 La ruta local del cliente donde montar el recurso compartido del servidor. 
sgrp=""
 Nombre del grupo o grupos separados por comas cuyos miembros están permitidos para montar el recurso.

Para situarse dentro de la carpeta personal del usuario se puede usar ~ o una ruta absoluta usando variables como %(USER) o %(DOMAIN). Hay más variables que se pueden ver con el siguiente comando: 

man pam_mount.conf

Unir un cliente Windows a un controlador de dominio

1. Primero hay que configurar como DNS del cliente la IP del servidor / controlador de dominio.

2. En la sección "Cambios en el dominio o nombre de equipo" se asignará un nombre de equipo identificativo y se debe especificar el nombre de dominio del servidor.

Para unirse al dominio pedirá el usuario administrator y su contraseña asignada.

3. Hay que reiniciar el equipo y luego tendríamos que ser capaces de poder iniciar sesión con un usuario del dominio.

SSSD: Unir un cliente Linux a un controlador de dominio

Importante: Esto es una manera alternativa más fácil pero limitada para unir un cliente al dominio. Es mejor usar SAMBA: explicado aquí.


1. En el cliente hay que instalar los paquetes necesarios:

apt-get install -y realmd sssd sssd-tools libnss-sss libpam-sss adcli samba-common-bin oddjob oddjob-mkhomedir packagekit

2. Ahora hay que comprobar que el dominio del servidor sea visible desde el cliente:

realm discovery [Nombre_dominio].[TLD]

3. Para unirse al dominio hay que usar el usuario Administrador. Para ello se debe ejecutar el siguiente comando e ingresar la contraseña que pida: 

realm join [Nombre_dominio].[TLD] -U administrador

4. Después de unirnos al dominio, deberiamos ser capaces de ver la información de un usuario del dominio:

id [Usuario_del_dominio]

5. Es importante quitar o comentar en el fichero /etc/sssd/sssd.conf una línea que dice services = nss, pam.

Además, en el mismo fichero hay que poner el valor de la siguiente línea en false:

use_fully_qualified_names = false

Opcional: Se puede indicar en SSSD que se quiere usar UIDs y GIDs personalizados del servidor. Para ello hay que editar el siguiente fichero:

nano /etc/sssd/sssd.conf

Deshabilitamos la siguiente línea poniendo como valor en false:

ldap_id_mapping = false

Y se añaden las siguientes líneas en la sección domain/Tu_Dominio:

ldap_user_uid_number = uidNumber
ldap_user_gid_number = gidNumber

Una vez configurado guardamos el fichero y eliminamos los UIDs y GIDs ya generados:

rm -rf /var/lib/sss/db/*

Y por último reiniciamos el servicio de SSSD:

systemctl restart sssd

Para comprobar que los usuarios cojan los UIDs correctos se puede usar el siguiente comando:

id [Usuario_del_dominio]

Habilitar el soporte de ACL de Windows en un cliente Linux

En el fichero de configuración de samba /etc/samba/smb.conf hay que añadir en la sección [global] las siguientes líneas:

vfs objects = acl_xattr
map acl inherit = yes
store dos attributes = yes

Asignar el permiso SeDiskOperatorPrivilege a un grupo del dominio

Este permiso permite modificar las ACLs de los recursos compartidos por un servidor Linux desde un equipo Windows.


1. Hay que ejecutar el siguiente comando desde el servidor Linux del dominio:

net rpc rights grant [Nombre_grupo_a_otorgar] SeDiskOperatorPrivilege -U administrator

Para ver los grupos del dominio con ese permiso se puede ejecutar el siguiente comando:

net rpc rights list privileges SeDiskOperatorPrivilege -U administrator

2. Finalmente se puede cambiar permisos de una compartida de la siguiente forma mediante un equipo Linux o Windows del dominio con un usuario que tenga el permiso SeDiskOperatorPrivilege:

[Nombre_recurso]
    path = /[Ruta_al_recurso]
    read only = no
