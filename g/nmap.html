NMAP

The Network Mapper

none

Comandos básicos 
nmap [Tipo] [Opciones] [Objetivo]
 Sintaxis básica. 
nmap --help
 Ayuda sobre el uso del comando. Guía completa.
Estados de una conexión TCP 
SYN → SYN/ACK → ACK
 La conexión TCP se estableció exitosamente. 
SYN → RA
 RA: Indica que se rechaza la conexión (RST) y que se confirma la recepción del SYN enviado (ACK). 
SYN → (No responde)
 El objetivo no responde porque puede estar apagado, el firewall filtra los paquetes o se perdió el paquete. 
SYN → SYN/ACK → (No recibe ACK)
 Nuestro host no responde a la conexión (método TCP-SYN). 
SYN → SYN
 Se produjo un error en el objetivo ya que responde con la flag SYN. 
FIN → FIN/ACK → ACK
 La conexión TCP se finalizó exitosamente.
Seleccionar el objetivo 
10.200.0.0/16
 Se escanearán todas las IPs de la dirección de red especificada. 
10.200.0.1
 Se escaneará solo la IP especificada. 
10.200.0.1 10.200.0.2
 Se escanearán varias IPs separadas por espacios. 
10.200.0.0-20
 Se escanearán todas las IPs de un rango. 
-iL [Ruta_fichero]
 También se pueden almacenar las IPs en un fichero del sistema separando cada IP/FQDN mediante saltos de línea.
Puertos a escanear 
-p-
 Todos los 65.535 puertos. 
-p 22
 Un puerto específico. 
-p 22,80,443
 Un conjunto de puertos separados por comas. 
-p 22-443
 Un rango de puertos. 
-p U:53,67,68,T:22,80,443,445,389
 Los puertos UDP 53, 67, 68 (U:) y los puertos TCP 22, 80, 443, 445, 389 (T:). 
-F
 Los 100 primeros puertos más importantes clasificados por Nmap. 
--top-ports=10
 Los 10 puertos más importantes clasificados por Nmap.
Escaneos TCP 
-sS
 Funcionamiento del escaneo TCP-SYN:
  • Se envía al objetivo un paquete con la flag SYN
    • Si responde con la flag SYN/ACK, se clasifica como 'open'
    • Si responde con RA (RST + ACK), se clasifica como 'closed'
    • Si no se recibe una respuesta, se clasifica como 'filtered'
Es el tipo de escaneo predefinido si no se especifica otro. 
-sT
 Funcionamiento del escaneo TCP-CONNECT:
  • Se envía al objetivo un paquete con la flag SYN
    • Si responde con SYN/ACK, nuestro host le enviará la flag ACK para completar la conexión, clasificando así el puerto como 'open'
    • Si responde con RA (RST y ACK), se clasifica como 'closed'
    • Si no se recibe una respuesta, se clasifica como 'filtered'
 
-sA
 Funcionamiento del escaneo TCP-ACK:
  • Se envía al objetivo un paquete con la flag ACK
    • Si se recibe la flag RST entonces el puerto permite una conexión. Posibles estados: 'open' o 'closed'
    • Si no se recibe una respuesta, el puerto puede estar bloqueado asi que se clasificará como 'filtered'
 
-sN
 Funcionamiento del escaneo TCP-NULL:
  • Se envía al objetivo un paquete sin ninguna flag TCP activada
    • Si el puerto está cerrado, el objetivo responderá con un paquete con la flag RST. Estado: 'closed'
    • Si no se recibe ninguna respuesta, se clasifica como 'open|filtered'
    • Si se recibe un error ICMP inalcanzable, se clasifica como 'filtered'
Escaneos UDP 
-sU
 Funcionamiento del escaneo UDP:
  • Se envía un paquete UDP al host
    • Si se recibe una respuesta, se clasifica como 'active'
    • Si se recibe un error 3 (inalcanzable), se clasifica como 'closed'
    • Si se recibe otro error diferente, se clasifica como 'open|filtered'
Escaneos ICMP / Descubrimiento 
-PE
 Funcionamiento del escaneo ICMP Echo Request:
  • Antes de enviar el paquete ICMP y, si nuestro host está en la misma red que el objetivo, se enviará un paquete ARP Request
    • Si recibe un ARP reply, el host está 'active'
    • Si no se recibe un ARP reply, se enviará un ICMP Echo Request
      • Si se recibe un ICMP reply, el host está 'active'
      • Si no se recibe respuesta o es inalcanzable, el host está 'inactive'
 
-sn
 Funcionamiento del Ping Scan:
  • Deshabilita por completo el escaneo de puertos y únicamente sondea qué equipos están conectados en la red
    • En red local: Se envían solicitudes ARP; si el objetivo responde, se clasifica como 'up'
    • Hacia hosts remotos: Se envían sondeos ICMP Echo, TCP SYN (:443), TCP ACK (:80) e ICMP Timestamp; con cualquier respuesta se clasifica como 'up'
    • Si no hay respuesta tras los reintentos, se clasifica como 'down'
Deshabilitar opciones 
--disable-arp-ping
 Deshabilita la resolución de direcciones MAC mediante solicitudes ARP que se realiza por defecto para poder enviar un paquete para averiguar si el host está activo, como por ejemplo en el escaneo ICMP Echo Request (-PE).
Ten en cuenta que el escaneo por ARP en redes locales es más fiable que averiguar el estado de un host mediante paquetes ICMP. 
-Pn
 Deshabilita el uso de paquetes ICMP Echo Request para averiguar si el host está activo. Una vez deshabilitado se presupone que el host está activo.
Información adicional
En cualquier momento se puede ver el tiempo estimado que queda hasta finalizar el escaneo pulsando la tecla "TABULADOR". 
-sL
 Esta opción no detecta el estado ni escanea los puertos de los hosts, solo lista los equipos que se escanearán antes de un escaneo real.
Realizará una consulta DNS inversa para averiguar el registro DNS pertenece a cada IP (se puede deshabilitar con el parámetro -n). 
-sV
 Determina el servicio que se ejecuta en cada puerto abierto, su versión y detalles adicionales. En algunos casos, la información del banner del servicio puede desvelar el sistema operativo. 
-O
 Envía paquetes modificados para que el sistema operativo responda y así poder averiguar mediante una base de datos interna qué tipo de sistema operativo puede ser. 
-n
 Deshabilita la resolución DNS. 
--packet-trace
 Nos da la información detallada de cada paquete enviado y recibido incluyendo las flags. Se indica que paquetes han sido enviados por nuestro host (SENT) y cuales se recibieron (RCVD). 
--reason
 Identifica la razón de porqué está activo un host. 
-vvv
 Con verbose se puede visualizar en tiempo real la información del escaneo. Cuantos más v haya, más información se recibirá. 
--stats-every=(Segundos)/s[o](Minutos)/m
 Se puede modificar el tiempo en minutos o segundos para que Nmap envie información. NO se puede indicar los minutos y segundos a la vez.
Optimizar tiempos de respuestas 
--initial-RTT-timeout [min]:[initial]:[max]
 min: Tiempo mínimo de espera permitido (por defecto es 100 ms).
initial: Tiempo máximo en el que se espera un paquete. Cuando reciba paquetes cambiará este valor para futuros paquetes según en el tiempo que tardó, pero nunca será menos que min y no más que max.
max: Tiempo máximo de espera permitido. 
--max-retries [Número_intentos]
 Intenta enviar un paquete si no lo recibe hasta x veces (por defecto son 10). 
--min-rate [Número_intentos]
 Nmap intentará igualar la tasa de paquetes que envía cada segundo con el número asignado en este parámetro. 
-T [0-5]
 El parámetro --min-rate se configura manualmente. Existen 6 plantillas predefinidas según niveles, siendo el nivel 0 el más lento y sigiloso y, el nivel 5, es el más rápido (tiene menos tiempo para averiguar el estado de un puerto) y detectable. El valor ideal es el nivel 3.
Exportar resultados 
-oA [Nombre_fichero]
 Exporta el resultado en 3 ficheros con formatos: .nmap, .xml y .gnmap. 
-oN [Nombre_fichero]
 Exporta el resultado en un fichero con formato: .nmap ~ salida normal de terminal. 
-oG [Nombre_fichero]
 Exporta el resultado en un fichero con formato: .gnmap ~ salida de terminal adaptado para hacer grep. 
-oX [Nombre_fichero]
 Exporta el resultado en un fichero con formato: .xml. 
xsltproc [Nombre_fichero].xml -o  [Nombre_fichero].html
 Una vez exportado a .xml se puede convertir a formato .html mediante un comando externo de Linux.
Scripts
Los scripts están hecho en LUA y están agrupados en varias categorías, ofreciendo funcionalidades diferentes.
Tipos de categorías (ver más):
  • auth: Determina credenciales de acceso.
  • broadcast: Descubrimiento de hosts.
  • brute: Intenta iniciar sesión en el servicio.
  • default: Predeterminados.
  • discovery: Evaluación de servicios accesibles.
  • dos: Buscar vulnerabilidades con DoS.
  • exploit: Explota vulnerabilidades conocidas.
  • external: Se utilizan servicios externos.
  • fuzzer: Identificar vulnerabilidades con paquetes.
  • intrusive: Scripts intrusivos en el sistema.
  • malware: Se comprueba si está infectado.
  • safe: No se realizan accesos intrusivos.
  • version: Detección de versiones de servicios.
  • vuln: Buscar vulnerabilidades específicas.
 
-sC
 Se utilizarán los scripts predeterminados (default). 
--script [Nombre_script/Nombre_categoría]
 Con este parámetro se puede utilizar uno o varios script identificados por su nombre. 
-A
 Es un parámetro comodín que combina la detección del S.O. (-O), la detección de versiones y servicios (-sV), utiliza los scripts predeterminados (-sC) e identifica cada "salto" que da el paquete (--traceroute).
Evasión de IPs
El sistema de detección de intrusiones (IDS) y sistema de prevención de intrusiones (IPS) son componentes basados en software.
IDS escanea la red en busca de posibles ataques, los analiza (coincidencia de patrones y firmas) e informa cualquier ataque detectado.
IPS complementa el IDS tomando medidas defensivas específicas si se hubiera detectado un posible ataque.
Recomendación:
Con una VPS se permite dividir la carga de los escaneos que se realicen y también se puede saltar los bloqueos que haya impuesto el sistema objetivo hacia nuestro host. También, si el objetivo detecta un ataque desde nuestra red doméstica, puede contactar con el ISP para detener el ataque bloqueando la IP pública. 
-D RND:[Cantidad_IPs]
 Esta opción permite enviar el mismo paquete x cantidad de veces desde diferentes IPs pero siempre añadiendo nuestra IP real en la lista (IP spoofing).
Problema: Los routers e ISP si ven una IP de origen fuera de su rango de IPs pueden descartar el paquete para que no llegue al destino. 
-S [IP_origen]
 Esta opción permite manipular la IP de origen de los paquetes mediante el campo IP ID. Es importante que la IP exista para poder recibir las respuestas. Se puede usar la IP de una VPS diferente. 
-e [Interfaz_de_red]
 Esta opción permite enviar el paquete por diferentes interfaces a la predeterminada del sistema. 
--dns-server [Servidor1](,Servidor2)
 Esta opción permite cambiar el servidor DNS que responderá a las consultas durante el escaneo. 
--source-port [Puerto]
 Si un sistema, ya sea de origen o destino, bloquea las solicitudes pero se descubre que tiene puertos que pueden estar libres, como el puerto 53 en la mayoría de los casos, se puede enviar la solicitud por ese puerto para evadir el filtro del sistema.
Interpretación del S.O. según el TTL
El TTL (Time To Live) es un valor que se puede cambiar manualmente así que no es un método completamente fiable.
Se puede identificar el S.O. mediante firmas con el parámetro -O.

Posibles S.O. con el TTL 64: Linux, MacOS, Android, FreeBSD.
Posibles S.O. con el TTL 128: Windows.
Posibles S.O. con el TTL 255: Cisco IOS, Solaris.
Interpretación de tiempos de respuesta 
SENT (0.0381s) TCP host > destino S ...
SENT (1.0411s) TCP host > destino S ...
… Nmap done: ... scanned in 2.06 seconds
 En este caso llamado dropped se puede ver que se envia 2 paquetes SYN y en ninguno responde, dando un mayor tiempo de espera para intentar recibir una respuesta.
Posible causa: Un firewall descarta la conexión y no envía un paquete de vuelta haciéndonos esperar más tiempo. 
SENT (0.0381s) TCP host > destino S ...
RCVD (0.0487s) ICMP [Destino] Port unreachable (type=3/code=3)
… Nmap done: ... scanned in 0.05 seconds
 En este caso llamado rejected se puede ver que se envía 1 paquete SYN y el firewall rechaza la conexión con una paquete ICMP. Gracias a esto se espera mucho menos tiempo al recibir una respuesta.
Interpretación del estado de un puerto
open: Se estableció la conexión al puerto con TCP, UDP o SCTP.
closed: Se rechaza la conexión con la bandera RST.
filtered: No se puede saber su estado. El firewall puede hacer: reject o drop.
unfiltered: Solo pasa en el scan TCP-ACK donde se puede acceder al puerto pero no se puede determinar su estado.
open|filtered: Cuando un firewall o filtro de paquetes protege un puerto y no se obtiene una respuesta.
closed|filtered: En un IP ID idle scan, indica que no se pudo saber si el puerto está cerrado o bloqueado por un firewall.
Recoger información 
curl [Objetivo]:[Puerto]
 Muchos servidores al hacer esta solicitud devuelven un banner que puede contener información del sistema.
Los servidores web se encuentran entre los servicios más atacados porque se hacen accesibles y presentan un alto potencial de ataque. 
smbclient -L //[Objetivo]/ -N
 Al realizar esta conexión al puerto 445 (SMB) nos permitirá ver recursos compartidos accesibles, permisos e información del host.
Se puede probar a acceder a cada recurso compartido (share) sin contraseña y, una vez dentro aparecerá un prompt con "smb: \>". Comando: smbclient //<IP>/<share> -N

(-N: Modo sin credenciales; -L: Listar recursos compartidos) 
ftp [Objetivo] [Puerto]
 Con una conexión ftp se puede probar a autentificarnos con anonymous y ver información. 
telnet [Objetivo] [Puerto]
 Con una conexión telnet se puede intentar conectarnos en remoto al puerto 23 y probar si el servidor deja autentificarse como root sin contraseña. 
netcat -nv -p [Puerto_origen] [Objetivo] [Puerto_objetivo]
 Si el destino acepta conexiones si las enviamos desde un puerto determinado, se puede manipular ese campo y conectarnos para así obtener más información.
IMPORTANTE: El puerto 53 junto a otros es un servicio esencial y, en algunos casos, nos permite conectarnos si lo configuramos como puerto de origen.
Filtros de WireShark 
arp && eth.src == [Dirección_MAC]
 Se enseñan solo los paquetes ARP cuya MAC de origen sea la indicada. 
arp && eth.dst == [Dirección_MAC]
 Se enseñan solo los paquetes ARP cuya MAC de destino sea la indicada. 
arp && eth.src == [Dirección_MAC] || arp && eth.dst == [Dirección_MAC]
 Se enseñan solo los paquetes ARP cuya MAC de origen o destino sea la indicada. 
ip.addr == [Dirección_IP]
 Se enseñan solo los paquetes cuya IP de origen sea la indicada. 
ip.dst == [Dirección_IP]
 Se enseñan solo los paquetes cuya IP de destino sea la indicada. 
ip.addr == [Dirección_IP] || ip.addr == [Dirección_IP] || ...
 Se enseñan solo los paquetes cuya IP de origen sea una de las indicadas. 
dns.qry.name == [Nombre_dominio]
 Se enseñan solo los paquetes cuya consulta DNS esté relacionada con el nombre de dominio asignado.
