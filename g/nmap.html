NMAP

The Network Mapper

none

COMANDOS BÁSICOS
nmap [Tipo] [Opciones] [Objetivo] Sintaxis básica.
nmap --help Ayuda sobre el uso del comando. Guía completa.
ESTADOS DE UNA CONEXIÓN TCP
SYN → SYN/ACK → ACK La conexión TCP se estableció exitosamente.
SYN → RA RA: Indica que se rechaza la conexión (RST) y que se confirma la recepción del SYN enviado (ACK).
SYN → (No responde) El objetivo no responde porque puede estar apagado, el firewall filtra los paquetes o se perdió el paquete.
SYN → SYN/ACK → (No recibe ACK) Nuestro host no responde a la conexión (método TCP-SYN).
SYN → SYN Se produjo un error en el objetivo ya que responde con la flag SYN.
FIN → FIN/ACK → ACK La conexión TCP se finalizó exitosamente.

TIPOS DE ESCANEOS - TCP
-sS Funcionamiento del escaneo TCP-SYN:
  • Se envía al objetivo un paquete con la flag SYN
    • Si responde con la flag SYN/ACK, el puerto se clasifica como 'open'
    • Si responde con RA (RST + ACK), el puerto se clasifica como 'closed'
    • Si no se recibe una respuesta, el puerto se clasifica como 'filtered'

Es el tipo de escaneo predefinido si no se especifica otro.

Ventaja: Es rápido.
Problemas: Se necesita permisos de administrador para poder modificar los paquetes.
-sT Funcionamiento del escaneo TCP-CONNECT:
  • Se envía al objetivo un paquete con la flag SYN
    • Si responde con SYN/ACK, nuestro host le enviará la flag ACK para completar la conexión, clasificando así el puerto como 'open'
    • Si responde con RA (RST y ACK), el puerto se clasifica como 'closed'
    • Si no se recibe una respuesta, el puerto se clasifica como 'filtered'

La diferencia con el escaneo TCP-SYN es que en TCP-CONNECT se llega a completar la conexión TCP.

Ventajas: No provoca fallos en el servidor. Es más fiable en la detección. Menos detectable por sistemas IPS.
Problema: Más posibilidades de registrar la conexión en un log. Es más lento que escaneo TCP-SYN.
-sA Funcionamiento del escaneo TCP-ACK:
  • Se envía al objetivo un paquete con la flag ACK
    • Si se recibe la flag RST entonces el puerto permite una conexión. Posibles estados: 'open' o 'closed'
    • Si no se recibe una respuesta, el puerto puede estar bloqueado asi que se clasificará como 'filtered'

Ventajas: Es mucho más difícil de filtrar para firewalls y sistemas IDS/IPS ya que no se puede averiguar si el ACK forma parte de una conexión establecida. Permite descubrir información sobre el estado del firewall o del sistema sin iniciar una conexión.
Problema: No se puede averiguar si el puerto está en estado 'open' o 'closed'.
-sN Funcionamiento del escaneo TCP-Null:
  • Se envía al objetivo un paquete sin ninguna flag TCP activada (todos los bits en 0)
    • Si el puerto está cerrado, el objetivo responderá con un paquete con la flag RST. Estado: 'closed'
    • Si no se recibe ninguna respuesta, el puerto se clasificará como 'open|filtered'
    • Si se recibe un error ICMP inalcanzable (tipo 3), se clasificará como 'filtered'

Ventajas: Muy sigiloso. Permite eludir firewalls sin estado (stateless) o filtros que bloquean paquetes SYN convencionales, sin iniciar una conexión TCP completa.
Problema: Sistemas como Windows, Cisco y BSD no cumplen estrictamente la RFC 793 y devuelven RST en todos los puertos, mostrando erróneamente todos los puertos como 'closed'.
TIPOS DE ESCANEOS - UDP
-sU Funcionamiento del escaneo UDP:
  • Se envía un paquete UDP al host
    • Si se recibe una respuesta, el puerto se clasifica como 'active'
    • Si se recibe un error 3 (inalcanzable), el puerto se clasifica como 'closed'
    • Si se recibe otro error diferente, el puerto se clasifica como 'open|filtered'

Ventaja: Podemos hacer conexiones a servicios UDP, por ejemplo DNS que utiliza el puerto 53 TCP y UDP.
Problemas: Es más lento que un escaneo TCP. No sabemos si recibió el paquete al ser un protocolo sin estado.
TIPOS DE ESCANEOS - ICMP / DESCUBRIMIENTO
-PE Funcionamiento del escaneo ICMP Echo Request:
  • Antes de enviar el paquete ICMP y, si nuestro host está en la misma red que el objetivo, se enviará un paquete ARP Request aunque se puede omitir usando el parámetro "--disable-arp-ping".
    • Si recibe un ARP reply, el host está 'active'
    • Si no se recibe un ARP reply, se enviará un ICMP Echo Request
      • Si se recibe un ICMP reply, el host está 'active'
      • Si no se recibe respuesta o es inalcanzable, el host está 'inactive'

Problemas: Es muy detectable por sistemas IPS o firewalls.
-sn Funcionamiento del Ping Scan:
  • Deshabilita por completo el escaneo de puertos y únicamente sondea qué equipos están encendidos y conectados a la red
    • En red local (LAN con root): Se envían solicitudes ARP/NDP; si el objetivo responde, el host se clasifica como 'up'
    • Hacia hosts remotos: Se envían sondeos ICMP Echo, TCP SYN (puerto 443), TCP ACK (puerto 80) e ICMP Timestamp; con cualquier respuesta el host se clasifica como 'up'
    • Si no hay respuesta tras los reintentos, el objetivo se clasifica como 'down'

Ventajas: Es extremadamente rápido al omitir el análisis de los 1000 puertos por defecto.
Problema: Los hosts remotos protegidos por firewalls que bloquean ICMP y los puertos 80/443 pueden aparecer falsamente como 'down'.
DESHABILITAR OPCIONES
--disable-arp-ping Deshabilita la resolución de direcciones MAC mediante solicitudes ARP que se realiza por defecto para poder enviar un paquete, como por ejemplo en el escaneo ICMP Echo Request (-PE).
-Pn Deshabilita el uso de paquetes ICMP Echo Request para averiguar si el host está activo. Una vez deshabilitado se presupone que el host está activo.
INFORMACIÓN ADICIONAL
-sV Determina el servicio que se ejecuta en cada puerto abierto, su versión y detalles adicionales.
En algunos casos, la información del banner del servicio puede desvelar el S.O.
-n Deshabilita la resolución DNS.
--packet-trace Nos da la información detallada de cada paquete enviado y recibido incluyendo las flags.
Se indica que paquetes han sido enviados por nuestro host (SENT) y cuales se recibieron (RCVD).
--traceroute Identifica cada "salto" que da el paquete hasta que llega a su destino.
--reason Identifica la razón de porqué está activo un host.
-vvv Con verbose se puede visualizar en tiempo real la información del escaneo. Cuantos más v haya, más información recibiremos. En cualquier momento se puede ver el tiempo estimado que queda hasta finalizar el escaneo pulsando la tecla "ESPACIO".
--stats-every=(Segundos)/s[o](Minutos)/m Se puede modificar el tiempo en minutos o segundos para que Nmap envie información.
NO se puede indicar los minutos y segundos a la vez.
OPTIMIZAR TIEMPOS DE RESPUESTA
--initial-RTT-timeout min:initial:max min: Tiempo mínimo de espera permitido (el tiempo por defecto es de 100 ms).
initial: Tiempo máximo en el que se espera un paquete. Cuando lo reciba cambiará este valor para futuros paquetes en el tiempo que tardó pero nunca debe ser menos que min y no más que max.
max: Tiempo máximo de espera permitido.
--max-retries [Número_intentos] Intenta enviar un paquete si no lo recibe hasta x veces (por defecto son 10).
--min-rate [Número_paquetes] Nmap intentará igualar la tasa de paquetes que envía cada segundo con el número asignado en este parámetro.
-T [0-5] El parámetro --min-rate se configura manualmente, por ello existen 6 plantillas predefinidas según niveles. El nivel 0 es el más lento y sigiloso y, el nivel 5, es el más rápido y detectable. El valor ideal es el nivel 3.
EXPORTAR RESULTADOS
-oA [Nombre_archivo] Exporta el resultado en 3 formatos: [Nombre_archivo].nmap, [Nombre_archivo].xml y [Nombre_archivo].gnmap.
-oN [Nombre_archivo] Exporta el resultado en formato: [Nombre_archivo].nmap. Salida normal de terminal.
-oG [Nombre_archivo] Exporta el resultado en formato: [Nombre_archivo].gnmap. Salida de terminal adaptado para hacer grep.
-oX [Nombre_archivo] Exporta el resultado en formato: [Nombre_archivo].xml. Formato XML.
xsltproc [Nombre_archivo].xml -o [Nombre_archivo].html Una vez exportado a XML se puede convertir a HTML mediante un comando externo.
SCRIPTS
[EXPLICACIÓN] Los scripts están hecho en LUA y están agrupados en varias categorías, ofreciendo funcionalidades diferentes.
[CATEGORÍAS]
  • auth: Determina credenciales de acceso.
  • broadcast: Descubrimiento de hosts.
  • brute: Intenta iniciar sesión en el servicio.
  • default: Predeterminados.
  • discovery: Evaluación de servicios accesibles.
  • dos: Buscar vulnerabilidades con DoS.
  • exploit: Explota vulnerabilidades conocidas.
  • external: Se utilizan servicios externos.
  • fuzzer: Identificar vulnerabilidades con paquetes.
  • intrusive: Scripts intrusivos en el sistema.
  • malware: Se comprueba si está infectado.
  • safe: No se realizan accesos intrusivos.
  • version: Detección de versiones de servicios.
  • vuln: Buscar vulnerabilidades específicas.

Esto se puede aplicar a todos los puertos o solo a algunos con -p. Ver más scripts o categorías.
-sC Se utilizarán los scripts predeterminados (default).
--script [Nombre_script/Nombre_categoría] Con este parámetro se puede utilizar uno o varios script identificados por su nombre.
-A Es un parámetro comodín que combina la detección del S.O. (-O), la detección de versiones y servicios (-sV), utiliza los scripts predeterminados (-sC) e identifica cada "salto" que da el paquete (--traceroute).
EVASIÓN DE IDS E IPS
[EXPLICACIÓN] El sistema de detección de intrusiones (IDS) y sistema de prevención de intrusiones (IPS) son componentes basados en software.

IDS escanea la red en busca de posibles ataques, los analiza e informa cualquier ataque detectado. El análisis de los ataques se basa en la coincidencia de patrones y firmas.

IPS complementa el IDS tomando medidas defensivas específicas si se hubiera detectado un posible ataque. Si se detectan patrones se puede por ejemplo impedir los intentos de conexión pendientes.
[RECOMENDACIÓN] Con una VPS se permite dividir la carga de los escaneos que se realicen y también se puede saltar los bloqueos que haya impuesto el sistema objetivo hacia nuestro host.

También, si el objetivo detecta un ataque desde nuestra red doméstica, se puede contactar con el ISP para detener el ataque bloqueando el uso de la IP pública.
-D RND:[Cantidad_IPs] Esta opción permite enviar el mismo paquete x cantidad de veces desde diferentes IPs pero siempre añadiendo nuestra IP real en la lista (IP spoofing).

Problema: Los routers e ISP si ven una IP de origen fuera de su rango de IPs pueden descartar el paquete para que no llegue al destino.
-S [IP_origen] Esta opción permite manipular la IP de origen de los paquetes mediante el campo IP ID. Es importante que la IP exista para poder recibir las respuestas. Se puede usar la IP de una VPS diferente.
-e [Interfaz_de_red] Esta opción permite enviar el paquete por diferentes interfaces a la predeterminada del sistema.
--dns-server [Servidor1](,Servidor2) Esta opción permite cambiar el servidor DNS que responderá a las consultas durante el escaneo.
--source-port [Puerto] Si un sistema, ya sea de origen o destino, bloquea las solicitudes pero descubrimos que tiene puertos que pueden estar libres, como el puerto 53 en la mayoría de los casos, podemos enviar la solicitud por ese puerto para evadir el filtro del sistema.
INTERPRETACIÓN DE S.O. SEGÚN TTL
ttl 64 Posibles S.O.: Linux, MacOS, Android, FreeBSD.
ttl 128 Posibles S.O.: Windows.
ttl 255 Posibles S.O.: Cisco IOS, Solaris.
(Otros resultados) El TTL (Time To Live) es un valor que se puede cambiar manualmente así que no es un método completamente fiable. Se puede identificar el S.O. mediante firmas con el parámetro -O.
INTERPRETACIÓN DE TIEMPOS DE RESPUESTA
SENT (0.0381s) TCP host > destino S ...
SENT (1.0411s) TCP host > destino S ...
… Nmap done: ... scanned in 2.06 seconds 		Este caso llamado dropped se puede ver que se envia 2 paquetes SYN y en ninguno responde, dando un mayor tiempo de espera para intentar recibir una respuesta.
Posible causa: Un firewall descarta la conexión y no envía un paquete de vuelta haciéndonos esperar más tiempo.
SENT (0.0381s) TCP host > destino S ...
RCVD (0.0487s) ICMP [destino Port unreachable (type=3/code=3)
… Nmap done: ... scanned in 0.05 seconds 		Este caso llamado rejected se puede ver que se envia 1 paquete SYN y el firewall rechaza la conexión con una paquete ICMP. Gracias a esto se espera mucho menos tiempo al recibir una respuesta.
INTERPRETACIÓN DEL ESTADO DE UN PUERTO
'open' Se estableció la conexión al puerto con TCP, UDP o SCTP.
'closed' Se rechaza la conexión con la bandera RST.
'filtered' No se puede saber su estado. El firewall puede hacer: reject o drop.
'unfiltered' Solo pasa en el scan TCP-ACK donde se puede acceder al puerto pero no se puede determinar su estado.
'open|filtered' Cuando un firewall o filtro de paquetes protege un puerto y no se obtiene una respuesta.
'closed|filtered' En un IP ID idle scan, indica que no se pudo saber si el puerto está cerrado o bloqueado por un firewall.
RECOGER INFORMACIÓN
curl [Objetivo]:[Puerto] Muchos servidores al hacer esta solicitud devuelven un banner que puede contener información del sistema.
Los servidores web se encuentran entre los servicios más atacados porque se hacen accesibles y presentan un alto potencial de ataque.
smbclient -L //[Objetivo]/ -N Al realizar esta conexión al puerto 445 (SMB) nos permitirá ver recursos compartidos accesibles, permisos e información del host.
Podemos probar a acceder a cada recurso compartido (share) sin contraseña y, una vez dentro aparecerá un prompt con "smb: \>". Comando: smbclient //<IP>/<share> -N

(-N: Modo sin credenciales; -L: Listar recursos compartidos)
ftp [Objetivo] [Puerto] Con una conexión ftp podemos probar a autentificarnos con anonymous y ver información.
telnet [Objetivo] [Puerto] Con una conexión telnet podemos intentar conectarnos en remoto al puerto 23 y probar si el servidor deja autentificarse como root sin contraseña.
netcat -nv -p [Puerto_origen] [Objetivo] [Puerto_objetivo] Si vemos que el destino acepta conexiones si las enviamos desde un puerto determinado, podemos manipular ese campo y conectarnos para así obtener más información.
IMPORTANTE: El puerto 53 junto a otros es un servicio esencial y, en algunos casos, nos permite conectarnos si lo configuramos como puerto de origen.
