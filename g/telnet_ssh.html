TELNET

Teletype Network

none

Configuración de un cliente Linux

En el cliente hay que instalar el servicio correspondiente:

apt-get update
apt-get install -y telnet

En el firewall hay que permitir el paso del puerto 23 - TCP (TELNET):

ufw allow 23

Conectarse a otro equipo con credenciales desde un cliente Linux y Windows

El siguiente comando permite crear una sesión TELNET hacia un equipo remoto:

telnet [IP/FQDN del equipo remoto] (Puerto_servidor)

Solicitará un usuario y contraseña dle sistema remoto para autentificarse. Las credenciales NO viajan cifradas así que pueden ser interceptadas con facilidad.

SSH (Linux)

Secure Shell


Configuración en un equipo

Tanto en el cliente como en el servidor se puede instalar el paquete ssh , que incluye los paquetes openssh-client y openssh-server:

apt-get update
apt-get install -y ssh

En el firewall hay que permitir el paso del puerto 22 - TCP (SSH):

ufw allow 22

Por último hay que verificar el estado del servicio SSH:

systemctl status ssh

Como conectarse a otro equipo con credenciales desde un cliente

El siguiente comando permite crear una sesión SSH con un usuario de un equipo mediante su contraseña:

ssh (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

El parámetro -p permite indicar el puerto del servicio SSH del equipo remoto. Por defecto intenta conectarse al puerto 22.

Como conectarse a otro equipo con claves desde un cliente

1. Con el usuario que va a realizar la sesión SSH en el equipo cliente se debe generar una clave personal:

ssh-keygen -t ed25519 -C "[Descripción de la clave]"
 Crea una clave de tipo ED25519. 
ssh-keygen -t rsa -b 4096 -C "[Descripción de la clave]"
 Crea una clave de tipo RSA de 4096 bits.

Se solicitará la ruta donde se guardará la clave privada. Por defecto se guarda en la carpeta ~/.ssh.

También solicitará una "passphrase", que se utilizará para poder descifrar la clave y guardarla en memoria RAM. Se suele dejar vacía para automatizar un proceso, aunque configurarla da mayor seguridad.

2. Se puede comprobar en la ruta por defecto que se crearon las claves pública y privada:

ls -l ~/.ssh/

La clave pública tiene permisos locales de lectura (r) para todos los usuarios.
La clave privada tiene permisos locales de lectura y escritura (rw) solo para el usuario propietario.

3. Ahora hay que copiar la clave pública en el usuario del equipo remoto:

ssh-copy-id -i ~/.ssh/id_[XXX].pub [Nombre_usuario]@[IP/FQDN del equipo remoto]

Hay que escribir "yes" para permitir conectarse con el equipo remoto.
Una vez copiado se puede comprobar en el equipo remoto que aparece la clave pública en su fichero de claves autorizadas: 

cat ~/.ssh/authorized_keys

Nota: Para copiar la clave al usuario root se debe permitir la directiva PermitRootLogin en el fichero de configuración /etc/ssh/sshd_config temporalmente o se puede hacer directamente copiando el contenido del fichero de la clave pública en el fichero /root/.ssh/authorized_keys.

4. Por último hay que comprobar que al crear una sesión SSH no pide la contraseña del usuario ya que este usuario del equipo remoto tiene la clave pública copiada:

ssh (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

Si el nombre del fichero de la clave SSH es distinto al nombre por defecto, hay que especificar con el parámetro -i la ruta donde se sitúa la clave:

ssh -i [Ruta_fichero_clave] (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

Políticas de seguridad del servicio sshd

Dentro del fichero /etc/ssh/sshd_config se pueden configurar las siguientes políticas individualmente:

PubkeyAuthentication yes
 Permite el inicio de sesión con claves públicas. 
PasswordAuthentication no
 Prohibe el inicio de sesión con contraseña. 
PermitRootLogin no
 Prohibe el inicio de sesión con el usuario root. 
PermitRootLogin prohibit-password
 Prohibe el inicio de sesión con contraseña para el usuario root.

Tras modificar alguna política hay que reiniciar el servicio sshd para aplicar los cambios:

systemctl restart sshd

Definir Aliases en un cliente

En el siguiente fichero de configuración del usuario se permite definir equipos y asignarles un nombre para ahorrar tiempo al iniciar sesiones remotas con SSH:

nano ~/.ssh/config

Dentro del fichero se puede tener varios bloques con el siguiente formato:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto] # Obligatorio
    User [Nombre_usuario]                # Opcional
    IdentityFile [Ruta_clave_privada]    # Opcional

Gracias a ese bloque de configuración ahora se puede crear sesiones SSH directamente con el nombre del alias que asignamos en el fichero:

ssh [Nombre_alias]

El alias anterior es lo mismo que ejecutar el siguiente comando:

ssh -i [Ruta_clave_privada] (Nombre_usuario)@[IP/FQDN del equipo remoto]

El alias se aplica a un solo usuario. Para que todos todos los usuarios puedan usar el alias, se debe configurar en el fichero de configuración: /etc/ssh/ssh_config.

Cargar una clave privada en memoria en un cliente

Estos pasos guardan temporalmente la clave SSH en memoria para no tener que introducir la passphrase cada vez que se utiliza durante la sesión:

1. Primero hay que iniciar el programa ssh-agent:

eval $(ssh-agent -s)

2. Luego, se debe añadir la clave privada al ssh-agent:

ssh-add [Ruta_clave_privada]

3. Por último, se puede listar las claves que actualmente tiene cargadas el agente para comprobar que la clave del paso 2 se ha cargado correctamente:

ssh-add -l

Crear túneles SSH

En los siguientes comandos se utiliza la opción -N para que no se abra una terminal remota, manteniendo solo la conexión abierta para el túnel.

Con la opción -L (Local Forwarding) se crea un túnel que redirige todo el tráfico del puerto del servidor hacia un puerto local:

ssh -N -L [Puerto_local]:localhost:[Puerto_remoto] (Nombre_usuario)@[IP_servidor]

Esto permite acceder a un servicio protegido en un puerto de forma cifrada.


Con la opción -R (Remote Forwarding) se crea un túnel que redirige todo el tráfico del puerto local hacia un puerto del servidor remoto:

ssh -N -R [Puerto_remoto]:localhost:[Puerto_local] (Nombre_usuario)@[IP_servidor]

Esto permite que cualquier usuario que acceda al puerto del servidor remoto redirija el tráfico hacia el puerto local sin necesidad de exponer directamente este puerto a Internet.


Con la opción -D se redirecciona el tráfico HTTP por un socket a un servidor SSH. Pasos de configuración:

1. En el servidor SSH hay que editar el fichero /etc/ssh/sshd_config y añadir/cambiar los siguientes parámetros:

AllowTcpForwarding yes
GatewayPorts yes

2. Luego, en el servidor SSH hay que reiniciar el servicio sshd:

systemctl restart sshd

3. En el cliente SSH hay que crear un nuevo socket hacia el servidor para poder transmitir la información del navegador:

ssh -N -C -D 2021 (Nombre_usuario)@[IP_servidor]

4. En el navegador del cliente hay que configurar la red a Configuración manual de proxy, configurando un socket con la dirección IP 127.0.0.1, el puerto asignado 2021 y por último elegir la opción SOCKS Host.


Con autossh se permite reconectar la conexión del túnel en caso de que caiga.
Para utilizarlo solo hay que cambiar el comando ssh por autossh -M 20000, donde el parámetro -M indica el puerto de monitorización: 

autossh -M 20000 -N -L [Puerto_local]:localhost:[Puerto_remoto] (Nombre_usuario)@[IP_servidor]
autossh -M 20000 -N -R [Puerto_remoto]:localhost:[Puerto_local] (Nombre_usuario)@[IP_servidor]
autossh -M 20000 -N -C -D 2021 (Nombre_usuario)@[IP_servidor]

Para arrancar el túnel automáticamente al iniciar el sistema hay que crear un nuevo servicio de systemctl - guía.

Crear una sesión SSH X11 en un cliente

Pasos a ejecutar en el servidor SSH:

1. Primero hay que instalar el paquete xauth:

apt-get install -y xauth

2. Luego hay que editar el fichero /etc/ssh/sshd_config y añadir/cambiar el siguiente parámetro:

X11Forwarding yes

3. Para aplicar los cambios del paso anterior hay que reiniciar el servicio sshd:

systemctl restart sshd

En el cliente SSH con interfaz gráfica hay que crear una conexión hacia el servidor de tipo X11 con el parámetro -X:

ssh -X (Nombre_usuario)@[IP_servidor]

Desde la sesión SSH con X11 se puede ejecutar cualquier programa con interfaz gráfica. El programa se ejecutará en el servidor, pero la interfaz gráfica se verá desde el escritorio del cliente.

SSH (Windows)

Secure Shell


Configuración en un equipo Windows

Primero se debe iniciar el servicio de SSH:

Start-Service sshd

Luego hay que configurar el servicio de SSH para que se inicie automáticamente:

Set-Service -Name sshd -StartupType 'Automatic'

Por último hay que habilitar el puerto 22 en el firewall desde las reglas de entrada y salida.

Como conectarse a otro equipo con credenciales desde un cliente

El siguiente comando permite crear una sesión SSH con un usuario de un equipo mediante su contraseña:

ssh (Nombre_usuario)@[IP/FQDN del equipo remoto]
