TELNET

Teletype Network

none

Configuración de un cliente Linux

En el cliente hay que instalar el servicio correspondiente:

apt-get update
apt-get install -y telnet

En el firewall hay que permitir el paso del puerto 23 - TCP (TELNET):

ufw allow 23

Conectarse a otro equipo

El siguiente comando permite crear una sesión TELNET hacia un equipo remoto:

telnet [IP/FQDN del equipo remoto] (Puerto_servidor)

Solicitará un usuario y contraseña dle sistema remoto para autentificarse. Las credenciales NO viajan cifradas así que pueden ser interceptadas con facilidad.

SSH

Secure Shell


Configuración en un servidor Linux

En el servidor hay que instalar el paquete de SSH, que incluye las funcionalidades de un cliente y servidor:

apt-get update
apt-get install -y ssh

En el firewall hay que permitir el paso del puerto 22 - TCP (SSH):

ufw allow 22

Por último hay que verificar el estado del servicio SSH:

systemctl status ssh

Configuración en un servidor Windows

Primero se debe iniciar el servicio SSH:

Start-Service sshd

Luego hay que configurar el servicio SSH para que se inicie automáticamente:

Set-Service -Name sshd -StartupType 'Automatic'

Por último hay que habilitar el puerto 22 en el firewall desde las reglas de entrada y salida.

Conectarse a otro equipo con credenciales desde un cliente Linux y Windows

El siguiente comando permite crear una sesión SSH con un usuario de un equipo mediante su contraseña:

ssh (Nombre_usuario)@[IP/FQDN del equipo remoto]

Puede que en Linux se tenga que instalar el paquete de SSH, que incluye las funciones del cliente y servidor:

apt-get install -y ssh

Conectarse a otro equipo con claves desde un cliente Linux

1. Con el usuario que va a realizar la sesión SSH en el equipo cliente se debe generar una clave SSH ED25519:

ssh-keygen -t ed25519 -C "[Descripción de la clave]"

Pedirá una ruta donde se guardará la clave privada. Por defecto se guarda en la carpeta ~/.ssh.
También pedirá una "passphrase" que se utilizará para poder descifrar la clave y guardarla en memoria RAM.

2. Se puede comprobar en la ruta por defecto que se crearon las claves pública y privada:

ls -l ~/.ssh/

La clave pública ~/.ssh/id_XXX.pub tiene permisos de lectura (r) para todos los usuarios.
La clave privada ~/.ssh/id_XXX tiene permisos de lectura y escritura (rw) solo para el usuario propietario.

3. Ahora hay que copiar la clave pública en el fichero ~/.ssh/authorized_keys del usuario del equipo remoto:

ssh-copy-id -i ~/.ssh/id_[XXX].pub [Nombre_usuario]@[IP/FQDN del equipo remoto]

Hay que escribir "yes" para permitir conectarse con el equipo remoto.
Una vez copiado se puede comprobar en el equipo remoto que aparece el mismo contenido que la clave pública en su fichero de claves autorizadas: 

cat ~/.ssh/authorized_keys

4. Por último hay que comprobar que al crear una sesión SSH no pide la contraseña del usuario ya que este usuario del equipo remoto tiene la clave pública copiada:

ssh (Nombre_usuario)@[IP/FQDN del equipo remoto]

Definir equipos remotos en un cliente de Linux

En el siguiente fichero de configuración del usuario se permite definir equipos y asignarles un nombre para ahorrar tiempo al iniciar sesiones remotas con SSH:

nano ~/.ssh/config

Dentro del fichero se puede tener varios bloques con el siguiente formato:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto]
    User [Nombre_usuario]

Gracias a ese bloque de configuración ahora se puede crear sesiones SSH directamente con el nombre del alias que asignamos en el fichero:

ssh [Nombre_alias]

El comando anterior sería lo mismo que ejecutar lo siguiente:

ssh (Nombre_usuario)@[IP/FQDN del equipo remoto]

Redireccionar HTTP por un socket al servidor

1. Editar el fichero /etc/ssh/sshd_config en el servidor SSH y añadir/cambiar los siguientes parámetros:

AllowTcpForwarding yes
GatewayPorts yes

2. En el servidor hay que reiniciar el servicio SSHD:

systemctl restart sshd

3. Hay que crear un socket para poder transmitir la información por el:

ssh -C -D 2021 (USER)@[IP]

4. En el navegador del cliente hay que configurar la red a "Configuración manual de proxy", configurando un socket con la ip 127.0.0.1, el puerto asignado 2021 y elegir "SOCKS Host".

Abrir la GUI de un programa del servidor en el cliente

1. Editar el fichero /etc/ssh/sshd_config en el servidor SSH y añadir/cambiar:

X11Forwarding yes

2. En el servidor reiniciar el servicio SSH:

systemctl restart sshd

3. Conectarse con X11 al servidor:

ssh -X (USER)@[IP]

4. Abrir un programa mediante comandos.
