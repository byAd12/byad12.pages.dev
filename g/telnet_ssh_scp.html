TELNET

Teletype Network

Configuración de un cliente Linux

En el cliente hay que instalar el servicio correspondiente:

apt-get update
apt-get install -y telnet

En el firewall hay que permitir el paso del puerto 23 - TCP (TELNET):

ufw allow 23

Conectarse a otro equipo con credenciales desde un cliente Linux y Windows

El siguiente comando permite crear una sesión TELNET hacia un equipo remoto:

telnet [IP/FQDN del equipo remoto] (Puerto_servidor)

Solicitará un usuario y contraseña dle sistema remoto para autentificarse. Las credenciales NO viajan cifradas así que pueden ser interceptadas con facilidad.

SSH (Linux)

Secure Shell

Configuración en un equipo

Tanto en el cliente como en el servidor se puede instalar el paquete ssh , que incluye los paquetes openssh-client y openssh-server:

apt-get update
apt-get install -y ssh

En el firewall hay que permitir el paso del puerto 22 - TCP (SSH):

ufw allow 22

Por último hay que verificar el estado del servicio SSH:

systemctl status ssh

Como conectarse a otro equipo con credenciales desde un cliente

El siguiente comando permite crear una sesión SSH con un usuario de un equipo mediante su contraseña:

ssh (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

El parámetro -p permite indicar el puerto del servicio SSH del equipo remoto. Por defecto intenta conectarse al puerto 22.

Como conectarse a otro equipo con claves desde un cliente

1. Con el usuario que va a realizar la sesión SSH en el equipo cliente se debe generar una clave personal:

ssh-keygen -t ed25519 -C "[Descripción de la clave]"
 Crea una clave de tipo ED25519. 
ssh-keygen -t rsa -b 4096 -C "[Descripción de la clave]"
 Crea una clave de tipo RSA de 4096 bits.

Se solicitará la ruta donde se guardará la clave privada. Por defecto se guarda en la carpeta ~/.ssh.

También solicitará una "passphrase", que se utilizará para poder descifrar la clave y guardarla en memoria RAM. Se suele dejar vacía para automatizar un proceso, aunque configurarla da mayor seguridad.

2. Ahora hay que asignar permisos locales restrictivos para la carpeta ~/.ssh y a las claves privadas y públicas (ejecuta los comandos en el mismo orden):

chmod 700 ~/.ssh
(shopt -s extglob 2>/dev/null; chmod 600 ~/.ssh/id_!(*.pub))
chmod 644 ~/.ssh/*.pub

3. Ahora hay que copiar la clave pública en el usuario del equipo remoto:

ssh-copy-id -i ~/.ssh/id_[XXX].pub [Nombre_usuario]@[IP/FQDN del equipo remoto]

Hay que escribir "yes" para aceptar que la huella digital (fingerprint) es legítima.
Una vez copiado se puede comprobar en el equipo remoto que aparece la clave pública en su fichero de claves autorizadas: 

cat ~/.ssh/authorized_keys

Opciones para copiar la clave al usuario root:

  1. Se puede permitir las directivas PermitRootLogin y PasswordAuthentication en el fichero de configuración /etc/ssh/sshd_config temporalmente.
    • Recuerda reiniciar el servicio sshd para aplicar los cambios.

  2. O se puede hacer manualmente copiando el contenido del fichero de la clave pública (.pub) en el fichero /root/.ssh/authorized_keys del equipo remoto.
    • Se puede realizar para cualquier usuario del sistema usando sus ficheros ~/.ssh/authorized_keys.

4. Para comprobar que la clave pública SSH se copió correctamente se puede crear una sesión SSH hacia el equipo remoto. Si se configuró una "passphrase", antes de iniciar la sesión pedirá que se ingrese: 

ssh (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

Si el nombre del fichero de la clave SSH es distinto al nombre por defecto, hay que especificar con el parámetro -i la ruta donde se sitúa la clave:

ssh -i [Ruta_fichero_clave] (-p PUERTO) (Nombre_usuario)@[IP/FQDN del equipo remoto]

Políticas de seguridad del servicio sshd

Dentro del fichero /etc/ssh/sshd_config se pueden configurar las siguientes políticas individualmente:

PubkeyAuthentication yes
 Permite el inicio de sesión con claves públicas. 
PasswordAuthentication no
 Prohibe el inicio de sesión con contraseña. 
PermitEmptyPasswords no
 Prohibe el inicio de sesión a cualquier usuario que no tenga una contraseña. 
PermitRootLogin no
 Prohibe el inicio de sesión con el usuario root. 
PermitRootLogin prohibit-password
 Prohibe el inicio de sesión con contraseña para el usuario root.

Tras modificar alguna política hay que reiniciar el servicio sshd para aplicar los cambios:

systemctl restart sshd

Definir Aliases en un cliente

En el siguiente fichero de configuración del usuario se permite definir equipos y asignarles un nombre para ahorrar tiempo al iniciar sesiones remotas con SSH:

nano ~/.ssh/config

Dentro del fichero se puede tener varios bloques con el siguiente formato:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto] # Obligatorio
    User [Nombre_usuario]                # Opcional
    IdentityFile [Ruta_clave_privada]    # Opcional

Gracias a ese bloque de configuración ahora se puede crear sesiones SSH directamente con el nombre del alias que asignamos en el fichero:

ssh [Nombre_alias]

El alias anterior es lo mismo que ejecutar el siguiente comando:

ssh -i [Ruta_clave_privada] (Nombre_usuario)@[IP/FQDN del equipo remoto]

El alias se aplica a un solo usuario. Para que todos todos los usuarios puedan usar el alias, se debe configurar en el fichero de configuración: /etc/ssh/ssh_config.

Cargar una clave privada en memoria en un cliente

Estos pasos guardan temporalmente la clave SSH en memoria para no tener que introducir la passphrase cada vez que se utiliza durante la sesión:

1. Primero hay que iniciar el programa ssh-agent:

eval $(ssh-agent -s)

2. Luego, se debe añadir la clave privada al ssh-agent:

ssh-add [Ruta_clave_privada]

3. Por último, se puede listar las claves que actualmente tiene cargadas el agente para comprobar que la clave del paso 2 se ha cargado correctamente:

ssh-add -l

Crear túneles SSH

Configuración inicial:

1. Para permitir los túneles hay que configurar las siguientes políticas del fichero /etc/ssh/sshd_config:

AllowTcpForwarding yes # Permite la creación de túneles
GatewayPorts yes       # Permite que el túnel remoto escuche en todas las interfaces

2. Para aplicar los cambios hay que reiniciar el servicio sshd:

systemctl restart sshd

Tipos de túneles:

Nota: En los siguientes comandos se utiliza la opción -N para que no se abra una terminal remota, manteniendo solo la conexión abierta para el túnel.
También se puede usar la opción -f para que el túnel se ejecute en segundo plano.

Túnel Local Forwarding (-L):

ssh -N -L [Puerto_local]:localhost:[Puerto_remoto] (Nombre_usuario)@[IP/DNS_servidor]

Todo el tráfico que se envíe a Puerto_local se enviará de forma cifrada al puerto Puerto_remoto de la máquina localhost (el propio servidor remoto).

Si el servicio al que quieres acceder no está en el propio servidor SSH, sino en otra máquina de su red local, reemplaza localhost por esa IP o FQDN.


Túnel Remote Forwarding (-R):

ssh -N -R [Puerto_remoto]:localhost:[Puerto_local] (Nombre_usuario)@[IP/DNS_servidor]

Todo el tráfico que se envíe al puerto Puerto_remoto del servidor remoto se reenviará al puerto Puerto_local de la máquina localhost (el propio host que ejecuta el comando).

Si el servicio que se quiere exponer no se encuentra en la propia máquina donde se ejecuta el comando, reemplaza localhost por la IP o FQDN del equipo de la red local que aloje ese servicio.


Túnel SOCKS / Dynamic Port Forwarding (-D):

ssh -N -C -D [Puerto_local] (Nombre_usuario)@[IP/DNS_servidor]

Se redirecciona el tráfico HTTP por un socket a un servidor SSH para poder transmitir la información del navegador.

En el navegador del cliente hay que configurar la red a Configuración manual de proxy, configurando un socket con la dirección IP 127.0.0.1, el puerto asignado Puerto_local y por último elegir la opción SOCKS Host.

Como crear túneles con capacidad de reconexión:

Con autossh se permite reconectar la conexión del túnel en caso de que caiga.
Para utilizarlo solo hay que cambiar el comando ssh por autossh -M 20000, donde el parámetro -M indica el puerto de monitorización: 

autossh -M 20000 -N -L [Puerto_local]:localhost:[Puerto_remoto] (Nombre_usuario)@[IP/DNS_servidor]
autossh -M 20000 -N -R [Puerto_remoto]:localhost:[Puerto_local] (Nombre_usuario)@[IP/DNS_servidor]
autossh -M 20000 -N -C -D 2021 (Nombre_usuario)@[IP/DNS_servidor]

Para arrancar el túnel automáticamente al iniciar el sistema hay que crear un nuevo servicio de systemctl:

1. Primero hay que definir la configuración del servicio en un fichero /etc/systemd/system/nuevo-tunel.service:

[Unit]
Description=Túnel SSH
After=network-online.target
[Service]
User=tu_usuario_local
ExecStart=/usr/bin/autossh [OPCIONES PARA CREAR EL TÚNEL]
Restart=always
RestartSec=5s
[Install]
WantedBy=multi-user.target

2. Luego hay que habilitar e iniciar el nuevo servicio:

systemctl enable nuevo-tunel
systemctl start nuevo-tunel

Como crear un alias para un túnel:

En el fichero ~/.ssh/config se puede añadir un alias para un túnel SSH:

Para crear un alias de un túnel Local Forwarding:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto] # Obligatorio
    User [Nombre_usuario]                # Opcional
    LocalForward [Puerto_local] localhost:[Puerto_remoto]

Para crear un alias de un túnel Remote Forwarding:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto] # Obligatorio
    User [Nombre_usuario]                # Opcional
    RemoteForward [Puerto_remoto] localhost:[Puerto_local]

Para crear un alias de un túnel SOCKS / Dynamic Port Forwarding:

Host [Nombre_alias]
    Hostname [IP/FQDN del equipo remoto] # Obligatorio
    User [Nombre_usuario]                # Opcional
    DynamicForward [Puerto_local]

Crear una sesión SSH X11 en un cliente

Pasos a ejecutar en el servidor SSH:

1. Primero hay que instalar el paquete xauth:

apt-get install -y xauth

2. Luego hay que editar el fichero /etc/ssh/sshd_config y añadir/cambiar el siguiente parámetro:

X11Forwarding yes

3. Para aplicar los cambios del paso anterior hay que reiniciar el servicio sshd:

systemctl restart sshd

En el cliente SSH con interfaz gráfica hay que crear una conexión hacia el servidor de tipo X11 con el parámetro -X:

ssh -X (Nombre_usuario)@[IP/DNS_servidor]

Desde la sesión SSH con X11 se puede ejecutar cualquier programa con interfaz gráfica. El programa se ejecutará en el servidor, pero la interfaz gráfica se verá desde el escritorio del cliente.

SSH (Windows)

Secure Shell

Configuración en un equipo Windows

Primero se debe iniciar el servicio de SSH:

Start-Service sshd

Luego hay que configurar el servicio de SSH para que se inicie automáticamente:

Set-Service -Name sshd -StartupType 'Automatic'

Por último hay que habilitar el puerto 22 en el firewall desde las reglas de entrada y salida.

Como conectarse a otro equipo con credenciales desde un cliente

El siguiente comando permite crear una sesión SSH con un usuario de un equipo mediante su contraseña:

ssh (Nombre_usuario)@[IP/FQDN del equipo remoto]

SCP

Secure Copy Protocol

Cómo copiar ficheros desde/hasta un equipo remoto

Con el comando scp se pueden copiar ficheros desde el sistema local hacia otro sistema remoto (o al revés) utilizando SSH.

Sistema local → Sistema remoto:

scp [Ruta_sistema_local] (Nombre_usuario)@[IP/FQDN del equipo remoto]:[Ruta_sistema_remoto]

Sistema remoto → Sistema local:

scp (Nombre_usuario)@[IP/FQDN del equipo remoto]:[Ruta_sistema_remoto] [Ruta_sistema_local]

Además de rutas absolutas, se pueden utilizar rutas relativas al usuario remoto o local.

Para copiar carpetas completas hay que indicar el parámetro -r (recursivo).
Si el puerto del servicio SSH en la máquina remota no es el 22, se debe definir manualmente el parámetro -P seguido del número de puerto abierto.
